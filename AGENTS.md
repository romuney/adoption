Явные требования пользователя и подтверждённые ограничения Adoption имеют приоритет над общими советами. В споре playbook и builder смотри раздел 4 общего playbook; ранние инструкции и замеры — история, не состояние прода. Для небольших задач читай выбранные главы, а не весь playbook.

Текущий отчёт уже работает. GP-поставка 2026-10-23 подготовлена, но по сообщению владельца ещё не применена. Не перезаписывай `Единый лист — актуальные файлы/`. Экспериментальная новая поставка должна жить отдельно и использовать отдельные физические таблицы GP/ClickHouse; применение в прод выполняет владелец.

Для параллельного отчёта исходный актуальный ETL — [Proteus Adoption (4).yaml](<Proteus Adoption (4).yaml>), а не старый Helicopter.yaml. Требования: [docs/parallel/REQUIREMENTS.md](docs/parallel/REQUIREMENTS.md). [Новая поставка](<Параллельный отчёт — pa_next/0. Начни здесь.md>) собирается `tools/parallel/`; `Виджеты/`, старые поставки и пользовательский исходный YAML не переписываются. Сходимость всех чисел и направлений фильтров обязательна. Общие источники читать можно, все новые физические записи — только `pa_next_*`.

GP-таблицы `pa_next_*` создаются без имени схемы — в рабочей/временной схеме ноды Helicopter; запись в `usr_cross_data` запрещена. Межпараграфные и экспортируемые таблицы должны быть доступны другим соединениям, поэтому сессионный `CREATE TEMP` используется только для локального helper. Заголовки параграфов описывают действия по-русски. Пользователь выбрал переимпорт полного YAML для обновления экспериментальной ноды.

В `pa_next` по последнему запросу владельца от 16.11 штатная шапка борда может скрываться в просмотре, только если установлен рабочий Markdown-контрол из файла 14. Невидимая зона открывает/закрывает её кликом, не наведением; Tab сохраняет доступ к кнопкам. При отсутствующем/сломавшемся контроле, отсутствующем адресате переключения или target=_blank шапка остаётся штатной. CSS переключателя не должен требовать стандартный класс Markdown или соседство ссылок в одном p; контрольный ряд обнуляется до загрузки графика. Новые ссылки используют постоянный #app, старые #chart-id поддерживаются. Нельзя переключать pointer-events opener по его :focus до mouseup: это отменяет native anchor click. Основное состояние — URL :target, а не мышиный фокус. В режиме редактирования она всегда видна. Глобальная навигация Proteus не скрывается; шапки чартов и native filters остаются скрытыми. Не предлагай `edit=true` для входа в редактор: на текущем Proteus этот параметр вызывает ошибку (сообщение владельца 2026-11-14).

Диагностика живого `pa_next` от 14.11.2026: `#main-menu` отсутствует, но верх шапки борда — 48 px. Не обнуляй резерв навигации по отсутствию этого ID. Для обычного борда CSS сохраняет 48 px; встраивание без меню требует явного override на целевой grid. Подробности: [разбор диагностики](<Параллельный отчёт — pa_next/Проверки/UI — диагностика прода и CSS.md>).

Интерфейс `pa_next`: перетаскивание каталога не должно масштабировать шрифт аналитики даже на промежуточных кадрах. Каталог имеет минимум 420 px; аналитика — минимум 740 px, увеличиваемый по фактической ширине чисел KPI. Внутренняя таблица каталога растягивается вместе с панелью; названия отчётов — максимум три строки, включая выбранные, полный текст — в подсказке. Для дальнейшего освобождения места есть скрытие каталога. Полосы прокрутки не должны перекрывать данные; повторный запуск JS в том же iframe сохраняет прокрутку и раскладку.

Если выбранный период/фильтры требуют полной загрузки правой части, KPI, выводы и график заменяются одной общей областью загрузки под вкладками. Нельзя оставлять пустые KPI/выводы с индикатором только внутри графика. Валидный preview и результат из кэша остаются видимыми. Проверять весь экран ожидания и покрытие всех трёх областей, а не только скрытие старых чисел и отсутствие сдвигов.

Верхнее и нижнее видимые поля отчёта должны быть сопоставимы, а нижние края каталога и аналитики — совпадать. Измеряй суммарный отступ борда и iframe: без прокрутки на большом экране и после прокрутки до конца на ноутбуке. По последнему требованию владельца не резервировать отдельные поля под скролл ни через padding, ни через scrollbar-gutter: сами полосы должны быть тонкими. Края общей шапки и тела совпадают, ручка находится по центру видимого зазора. В режиме прокрутки аналитика занимает всю видимую высоту; при прокрутке до конца от шапки отчёта не должна оставаться линия.


ЦА по конкретным людям: `ca_login_f` / `ca_master_f`, ввод из Excel и ручными разделителями; OR внутри списка, AND с остальными условиями. Master ID — текстовый `mdm_employee_rk`, разрешаемый через отдельную `pa_next_person_id_map` с приоритетом MDM и существующей канонизацией логинов. Только текущий штат задаёт базу ЦА; неизвестный непустой список даёт пустую ЦА, а не «всех». Уволенный ID нельзя связывать с чужим переиспользованным логином; неоднозначность не разрешать ANY/min. UI сохраняет список в черновик, общий Apply запускает запрос. До SQL нельзя выдавать число введённых идентификаторов за число найденных людей.

При расширении набора фильтров сохраняй совместимость бизнес-ключей кэша в уже открытом iframe: отсутствующий новый фильтр не должен менять прежний ключ. Анимации KPI не участвуют в модели, доступное итоговое число остаётся точным, reduced motion отключает эффекты. Изменения анимационного текста через childList способны запускать лишние замеры viewport; используй существующий Text.nodeValue.

Полосы прокрутки pa_next скрыты в покое, появляются от прокрутки или движения у края и исчезают после паузы около секунды; размеры полосы при этом не меняются. В таблицах разрешено использовать 6 px существующего правого поля карточки: thumb смещается вправо, ширина данных сохраняется. Не возвращать показ полосы на всё время hover всей таблицы. Forced colors сохраняет системную видимость. Название Proteus Adoption, помощь и CROSS DATA находятся отдельной строкой над периодом/условиями.
