# Proteus Adoption

Рабочая ветка — `new`. Используй существующий checkout; отдельный worktree — только по просьбе пользователя. Перед записью проверь Git и сохрани чужие изменения.

| Задача | Точка входа |
|---|---|
| ClickHouse: SQL, схема, производительность | [ClickHouse Best Practices](.agents/skills/clickhouse-best-practices/SKILL.md), затем ограничения Proteus ниже |
| Интерфейс, доступность, UX | [Web Design Guidelines](.agents/skills/web-design-guidelines/SKILL.md); при недоступной сети — [закреплённые правила](docs/vendor/web-interface-guidelines/command.md), явно отметив версию |
| Proteus: датасеты, чарты, фильтры, доступ, кэш, поставка | [Proteus Playbook](.agents/skills/proteus-playbook/SKILL.md) — короткая маршрутизация по задаче |

[Аудит и обновление знаний](docs/knowledge/README.md). Навыки в `.agents/skills/` доступны для обнаружения Codex; реальную автоматическую активацию нужно отдельно проверить в новом чате. `skills/` — локальные материалы, не обещание автоматической активации.

Сведения о ClickHouse 24.8, Proteus/Superset 2.1.0 и sqlparse 0.4.3 с патчем документированы, но текущий прод независимо не проверен. Применяй интернет-рекомендации только после проверки совместимости. В частности, запросы к `system.*`, SHOW и SETTINGS из ClickHouse skill не разрешены автоматически в SQL Lab Proteus. Не подключай MCP/CLI и не считай корпоративный доступ настроенным только потому, что это описано в навыке.

Явные требования пользователя и подтверждённые ограничения Adoption имеют приоритет над общими советами. В споре playbook и builder смотри раздел 4 общего playbook; ранние инструкции и замеры — история, не состояние прода. Для небольших задач читай выбранные главы, а не весь playbook.

Текущий отчёт уже работает. GP-поставка 2026-10-23 подготовлена, но по сообщению владельца ещё не применена. Не перезаписывай `Единый лист — актуальные файлы/`. Экспериментальная новая поставка должна жить отдельно и использовать отдельные физические таблицы GP/ClickHouse; применение в прод выполняет владелец.
