# Утверждённая ЦА отчёта — план внедрения

Владелец отчёта собирает в конструкторе ЦА по атрибутам и структуре и
фиксирует: «это целевая аудитория моего отчёта». Дальше:

- вкладка «Аудитория» **по умолчанию** считает охват по утверждённой ЦА, а не
  по тому, как роздан доступ;
- отчёты с утверждённой ЦА **помечены** в каталоге, по пометке можно фильтровать;
- сохранять могут **только владельцы отчёта**, и это проверяет n8n.

```
UI (конструктор) ──POST {login из Proteus}──▶ n8n ta_save ──INSERT──▶ DLH (Trino): ta_event
                                                                          │
                                                  ноутбук ta_sync, раз в 15–30 мин
                                                                          ▼
                                                ClickHouse: adoption.ta_current, adoption.ta_event
                                                                          │
                                    ds_reports (пометка) · ds_audience (люди ЦА) ◀── отчёт
```

| Файл | Что это |
|---|---|
| `docs/ta_saved/FLOW.md` | **как собрать флоу**: таблица DLH, контракт, ноды, замена заглушек, проверки, что передать мне |
| `n8n/ta_save.mock.json` | макет флоу для импорта; вызовы Trino — заглушки с мок-ответами |
| `n8n/trino_query.json` | подпроцесс: один SQL в Trino REST → `{rows, update_count}` |
| `notebooks/ta_sync_clickhouse.py` | ноутбук DLH → ClickHouse |
| этот файл | что меняется в отчёте и порядок работ |

## 1. Решения

| | |
|---|---|
| Кто вызывает | логин из Proteus (`user_name` при авторизации) приходит в теле запроса |
| Кто сохраняет | все владельцы отчёта, админов нет |
| Что храним | **условия названиями**, как в фильтрах; людей не храним |
| Разрезы | `lvl3`, `lvl4`, `stream`, `spec`, `exp`, `it`, `hq`, `adgroup`; поимённых списков нет |
| Логика | внутри разреза ИЛИ, между разрезами И — как в конструкторе сейчас |
| Единица | один отчёт (`dashboard_id`); сохранение на коллекцию — позже |
| DLH | Trino, журнал событий `ta_event` (только дописываем, каждая запись — версия) |
| В ClickHouse | ноутбук по расписанию, полная атомарная перезаливка |

ЦА пересчитывается каждый день по свежему mdm: новый аналитик в блоке сразу
попадает в ЦА. Если значение пропало из структуры (подразделение
переименовали), ноутбук помечает ЦА `stale`, и владелец её пересохраняет.

## 2. ClickHouse

`adoption.ta_current` — одна строка на отчёт с активной ЦА:

```sql
dashboard_id UInt64, version UInt32, ta_status LowCardinality(String),  -- active | stale
f_lvl3 Array(String), f_lvl4 …, f_stream …, f_spec …, f_exp …, f_it …, f_hq …, f_adgroup Array(String),
stale_values Array(String), audience_cnt_save UInt32, audience_cnt_now UInt32,
comment String, saved_by String, saved_at DateTime, loaded_at DateTime
```

`adoption.ta_event` — зеркало журнала (для истории версий в UI). DDL создаёт
сам ноутбук.

## 3. Как меняется отчёт

### 3.1 Датасеты

**`ds_reports`, секция `report`**: `LEFT JOIN adoption.ta_current`, четыре
поля — `ta_status` (`none` | `active` | `stale`), `ta_version`,
`ta_saved_by`, `ta_saved_at`. Этого хватает на пометку и фильтр.

**`ds_audience`**: сейчас ЦА области — объединение «как роздан доступ» по
отчётам. Становится: по каждому отчёту **утверждённая ЦА, если есть, иначе
доступ**, затем объединение.

```sql
WITH ta AS (SELECT * FROM adoption.ta_current WHERE dashboard_id IN {scope_ids})
SELECT e.login, ta.dashboard_id
FROM <mdm на последнюю дату> AS e          -- колонки lvl3 … hq уже названиями, ad_groups — массив
CROSS JOIN ta
WHERE (empty(ta.f_lvl3)    OR has(ta.f_lvl3,   e.lvl3))
  AND (empty(ta.f_lvl4)    OR has(ta.f_lvl4,   e.lvl4))
  AND (empty(ta.f_stream)  OR has(ta.f_stream, e.stream))
  AND (empty(ta.f_spec)    OR has(ta.f_spec,   e.spec))
  AND (empty(ta.f_exp)     OR has(ta.f_exp,    e.exp))
  AND (empty(ta.f_it)      OR has(ta.f_it,     e.it))
  AND (empty(ta.f_hq)      OR has(ta.f_hq,     e.hq))
  AND (empty(ta.f_adgroup) OR hasAny(ta.f_adgroup, e.ad_groups))
UNION DISTINCT
SELECT login, dashboard_id FROM <доступ>               -- как сейчас
WHERE dashboard_id IN {scope_ids}
  AND dashboard_id NOT IN (SELECT dashboard_id FROM ta)
```

Те же предикаты повторяют флоу (подсчёт `audience_cnt`), ноутбук
(`audience_cnt_now`) и `customAudience()` в макете. Значит, число в окне
сохранения, в журнале и на карточке отчёта одно и то же.

### 3.2 Вкладка «Аудитория»

| Источник ЦА | Когда | Подпись | Кнопки |
|---|---|---|---|
| **Утверждённая** | есть в `ta_current`, человек ничего не менял | «Утверждена владельцем · v3 · a.petrova, 12.10.2026» + комментарий | все: «Изменить условия», «Посмотреть по доступу» |
| **Черновик** | применил условия в конструкторе | «Черновик — не сохранён» | владелец: **«Сохранить как ЦА отчёта»**; все: «Вернуть утверждённую» |
| **Как роздан доступ** | ЦА нет или временно переключился | как сейчас | владелец: «Настроить и сохранить ЦА» |

- По умолчанию — утверждённая. `S.audDef.mode` получает третье значение
  `saved`, `audienceDef()` выбирает в порядке `draft → saved → access`.
- Не владелец видит кнопку сохранения выключенной, в подсказке — кто
  владельцы. Список владельцев UI берёт из каталога, но решает ответ n8n.
- Область из нескольких отчётов: сохранение выключено («ЦА сохраняется на
  один отчёт»), считается объединение по 3.1, подпись — «у 3 из 5 отчётов
  утверждённая ЦА, у остальных — как роздан доступ».
- Устаревшая ЦА (`stale`): владельцу — плашка «Значения больше не существуют:
  Департамент «…». Пересохраните ЦА».
- К утверждённой ЦА правило «широкой аудитории» (30%) не применяется: владелец
  сам сказал, что отчёт для всех.
- Окно сохранения: условия, сколько человек и у скольких доступ, отличие от
  текущей версии, поле «для кого отчёт». Ответы n8n: 409 → «Пока вы
  редактировали, d.sokolov сохранил v4» + «Открыть v4»; 403 и 422 — текстом.
- После 200 ЦА сразу показывается как утверждённая (из ответа), с пометкой
  «у остальных появится в течение 30 минут», пока датасет не догонит версию.

### 3.3 Вкладка «Отчёты»

- В каталоге у отчёта с ЦА — метка «ЦА» (нейтральный `sig-chip`: фиолетовый
  занят меткой «новый»), в подсказке — кто и когда утвердил; у `stale` — с
  предупреждением.
- В фильтре слева — переключатель **«с утверждённой ЦА»** рядом с «сертифицированные».
- Строки коллекций и владельцев: «ЦА: 7 из 12».

### 3.4 Макет (этот репозиторий)

1. `data.js`: `D.savedAudience` на ~30% отчётов (одна `stale`), `D.ME` и
   переключатель «смотреть как владелец / как гость».
2. `app.js`: три источника ЦА, кнопки из 3.2, окно сохранения, мок `saveTa()`
   с ответами флоу (200 / 403 / 409 / 422), метка и фильтр в каталоге.
3. `_test.js`: сохранение владельцем, гость → 403, конфликт версий, `stale`,
   объединение по области, совпадение числа в окне и на карточке.
