# Аудит: что можно вытащить из данных (вводная для макетирования)

## А. Поля факта, которые ЕСТЬ, но НЕ показаны (или почти)
| Поле | Что можно из него сделать |
|---|---|
| `created_dt` | Динамика создания отчётов (новые отчёты по неделям/месяцам); возраст отчёта; «молодые vs зрелые» отчёты по аудитории |
| `certified_by` | Доля сертифицированных просмотров; фильтр есть — графика нет |
| `collection_names` | Структура просмотров по коллекциям (top-коллекции, treemap/bar) |
| `ad_groups_dash` (доступ к отчёту) | Аудит прав: отчёты с открытым доступом vs по группам; охват AD-групп |
| `owners_string` (владельцы) | Топ авторов/владельцев по аудитории и просмотрам; отчёты без владельца |
| `experience_group_nm` (стаж) | Adoption по стажу (новички vs опытные) — сейчас только в таблице 641532 |
| `active_type_nm` | Отдельно «Стажёры» — целевая аудитория адаптации |
| `current_head_lvl_segment` | Сегменты руководителей (сейчас только под gating'ом Cross Data) |
| `company_fire_flg` | Отток: доля просмотров уволенных; retention когорт с учётом увольнений |
| `management_head_flg` | Руководители vs исполнители (фильтр есть, графика нет) |
| `system_nm` | Пока один значение — на будущее (proteus vs superset) |

## Б. Метрики, которые считаются из имеющихся полей без изменения ноды
1. **Stickiness** = WAU/MAU, DAU/MAU —«насколько ежедневный инструмент».
2. **Growth accounting**: new / returning / resurrected / churned по бакетам (first_action + наличие события в периоде) — «откуда рост».
3. **Частота**: распределение юзеров по числу активных дней за период (1 день / 2–5 / 6–20 / 21+); медиана просмотров на юзера.
4. **Глубина**: сколько разных отчётов смотрит юзер за период (1 / 2–3 / 4+); «моно-юзеры» vs «исследователи».
5. **Pareto отчётов**: какая доля просмотров дают топ-10/топ-20 отчётов; «длинный хвост» мёртвых отчётов (0 просмотров за N дней при published=1 — есть actual_flg).
6. **Retention curve** (агрегированная по когортам, а не хитмап): % возвращающихся на M1–M6 — одна линия вместо таблицы.
7. **Rolling retention** и churn: юзеры, не заходившие >30 дней (last_action) — «спящие», счётчик оживления.
8. **Покрытие (coverage) в динамике**: % сотрудников, заходивших хотя бы раз в месяц — сейчас покрытие только на вкладке 2 по бакетам, нет тренда по стримам/УС.
9. **Новое vs старое**: просмотры отчётов, созданных за последние 3 мес vs старее (created_dt).
10. **Time-to-first-view** для новых отчётов: created_dt → первый просмотр не-овнером (скорость распространения).

## В. Требует доработки ноды (кандидаты)
- `first_flg` (первый отчёт овнера) уже считается в legacy `proteus_dashboards`, но не экспортируется → новые авторы по времени.
- Таблица отчётов как отдельная dim (не из факта): все published отчёты, включая 0 просмотров (для «мёртвых отчётов» и полноценного каталога). Сейчас факт = только просмотры, непросматриваемые отчёты невидимы (кроме покрытия через mdm_employee_daily).
- Событие «экспорт/скачивание», если появится в event_physical_report — глубина использования.

## Г. Ограничения модели (помнить при макетировании)
- Факт = просмотры страниц; «юзер» = login; сервисные логины отфильтрованы (svc_mon_otpp, dashboard_id 13040 — сам борд).
- Периоды всегда «от max_date назад» (нет произвольного time-range из-за max_date-логики).
- Retention: когорты месячные, age 0–24, от first_action за 3 года; фильтрами не режется.
- Покрытие считается только по активным («Активная» + «Стажёры»).
- Сегментация руководителей видна только членам AD-группы helicopter_access_team_pd_cross.
