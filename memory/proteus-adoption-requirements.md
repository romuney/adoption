# Требования к новому дашборду (со слов владельца, 2026-09-14)

## Аудитория (3 персоны)
1. **Руководители BI-команд** — насколько их решения (борды) востребованы/покрыты.
2. **Заказчики бордов** — реально ли целевая аудитория, для которой делался борд, его использует.
3. **Аналитики** (обязательный ежедневный инструмент) — кем/когда используется, сколько времени прошло, кто постоянные пользователи а кто нет, с какой периодичностью.

## Ключевой пользовательский флоу (главный кейс)
«Я создал отчёт → пропушил (например, рассылкой) → сколько людей зашло? → выросло ли? → по конкретной УС / AD-группе: кто от этой группы вообще ходит → кто из покрытых ни разу не зашёл (кому стоит зайти) → кто постоянные, кто нет, периодичность».
Многие шаги этого флоу сейчас данными НЕ покрыты — их надо закрыть в новом макете.

## Требования-решения
- Вкладка **«Анализ целевой аудитории» обязательна** — единственное место, где анализируется не только кто зашёл, но и сколько людей от целевой аудитории (покрытие headcount'ом).
- Нужна понятность **на уровне каждого борда** (per-report target audience), её сейчас нет.
- Прокси целевой аудитории через AD-группы прав доступа — рабочий вариант для большинства кейсов, НО слишком утрированный для «широких» групп типа Tableau All (RLS-борды, группа почти у всего банка). Решение: не отбрасывать AD-подход, а **помечать «широкие» группы/борды** (размер группы > порога от headcount → «открытый доступ», покрытие по ним не показывать/показывать с оговоркой).
- Возможная отдельная вкладка «Целевая аудитория по AD-группе» (название черновое).

## Осуществимость на текущих данных (анализ Claude)
- **Per-report аудитория v1 — БЕЗ доработки ноды**: в факте есть `allowed_logins` (точечные права, точная аудитория) и `ad_groups_dash` (групповые права); состав AD-групп всех сотрудников есть в `mdm_employee_daily_proteus.ad_groups`. Виртуальный датасет: distinct (dashboard_id, ad_groups_dash, allowed_logins) из факта × разворот групп в сотрудников → покрытие отчёта + списки «не зашли ни разу». Ограничение v1: отчёты с 0 просмотров не видны (факт = просмотры).
- **Размеры групп / флаг «широкая»** — тоже считаемо: count по mdm_employee_daily_proteus, порог задаём (напр. >30% активного headcount или >1000 человек).
- **Периодичность/постоянство** — из факта: активные дни за период, интервалы между визитами (last/first), «спящие» (>30д без визита), частотные корзины. Данных достаточно.
- **Фаза 2 (доработка ноды)**: dim-таблица ВСЕХ отчётов (включая непросматриваемые), first_flg (новые авторы), инкремент вместо полной перечитки за 13 мес.
