# FIELDS — поля для «Измерений» Proteus (v7, 2026-09-22; лист «Аудитория» v2 — 2026-09-24)

Поля из SQL не попадают в `data` автоматически. Каждое поле нужно вручную
добавить в панель «Измерения» чарта с точным именем.
Правило синхрона: **имя в SQL == имя в «Измерениях» == ключ в `CFG.fields`**.
Любое расхождение — поле не дойдёт до графика (RETRO 17).
Типы в Proteus: `#` — число, `abc` — строка. Массивы (`colls`, `ages`,
`acts`) приходят строкой — JSON `["a","b"]` или Python-вид `['a', 'b']`
(строковые массивы ClickHouse Superset отдаёт через str()); `arr()` виджетов
разбирает оба вида и живой массив.

Лист «Отчёты» в v7 — ТРИ чарта на ТРЁХ датасетах:

| Чарт | Виджет | Датасет | Строк | Слушает | Эмитит |
|---|---|---|---|---|---|
| Шапка: период · опции · пилюли фильтров | `pa-strip.chart.js` | `pa_strip` (новый), одна строка эха | 1 | область каталога + людскую шину | `period_param`, `pub_f`, `act_f`, `exc_f`; сброс всего — `applyCrossFilter([])` |
| Каталог (788805) | `pa-reports-body.chart.js` | `pa_body_v42` (169602), куб v7 | ~12 тыс. | полоску + людскую шину | `mode_param` + `sel_f` (область) |
| Аудитория области: KPI · «Что видно» · Динамика · Кто смотрит · Закрепляемость | `pa-area.chart.js` | `pa_people` (новый) | ~2,3 тыс. | шапку + область | `lvl3_f`, `lvl4_f`, `spec_f`, `stream_f`, `adg_f`, `heads_f`, `login_f`, `exl_f`, `freq_f` |

Самовлияние у всех трёх ВЫКЛЮЧЕНО. Носители кросс-фильтров (`*_param`,
`*_f`) в SELECT датасетов НЕ выводятся — их читает джиня (паттерн 59922).

## Виджет 2: «Аудитория области» — `pa-area.chart.js` (новый чарт)

Датасет **pa_people** (новый), SQL — поставка 2026-09-22, файл 3 (запасной на дневном
факте — 3b, ответ тот же). Заменяет pa_who + pa_coh_v4 + KPI тела. Источники: `pa_pair`
(люди, маски периодов, когорты, MAU) и `pa_dash_bkt` (линия «Просмотры» в ts); дневной
факт — только в срезах `cut:*` панели «Аудитория». 30 колонок, ~1–5 тыс. строк: список —
**все** зрители области, упакованные по подразделениям (одна строка `list` на путь
оргструктуры, см. `k`), + узлы оргструктуры. Лимит строк **50 000** (с запасом на большое
дерево; весь Proteus на стенде — 1,2 тыс. строк, 42 тыс. человек, 3,7 МБ).

Формат упакованного списка (`section = 'list'`): `parent` — путь «УС-3 › … › УС-7»
(`''` — без атрибутов), `cnt` — людей в строке, `k` — люди через `\n`, поля через `\t`:
`логин · ФИО · специализация · стрим · стаж · рук. 1/0 · активных периодов · просмотров ·
последний визит YYYY-MM-DD · корзина 1–4 · новый 1/0 · MAU 1/0 · MAU пред. месяца 1/0`.
Колонки login…bin у `list` теперь NULL. Итоги групп при корзине частоты / настройках
списка и KPI при настройках списка (корзина на KPI не влияет) чарт считает сам по этим полям. Уровни УС — после нормализации: заглушки
(`-`, `—`, `…`, пробелы) = пусто, путь на них обрывается.

## Что считается в JS, а что в SQL

| Расчёт | Где | Почему |
|---|---|---|
| уникальные пользователи экрана, корзины, когорты, MAU | SQL (pa_people) | нужна дедупликация по людям — на клиенте её не сделать |
| маски активных периодов пар «отчёт × логин» | GP (pa_pair) | не зависят от фильтров — считаются раз в сутки |
| доли, дельты, наблюдения по порогам, сегменты, медианы когорт, кривая удержания, стек «новые/вернувшиеся/продолжающие» | JS | правило 2 скилла |
| фильтрация вкладок каталога друг по другу, поиск, сортировка, пагинация | JS (каталог) | без похода в базу |
| дерево групп, подсветка выбора, гашение пустых групп, поиск людей, настройки списка | JS (панель) | без похода в базу |
| ЦА (права / весь штат + условия), охват, воронка, сегменты, динамика ЦА, итоги групп «Кто из ЦА» | JS (панель «Аудитория») | смена ЦА без запроса; сервер отдаёт людей области |
| ЦА отчёта по правам (`pa_dash_ca`), состав групп прав (`pa_adg_member`) | GP | разворот AD-групп — раз в сутки, не на клик |
