## §1 Зачем отдельным чартом (решение владельца 2026-09-25)

Настройка ЦА жила плашкой внутри панели и требовала самовлияния панели. На бою оно не
срабатывало, и ЦА не применялась к самой панели. Строка — отдельный эмиттер `ca_*_f`, а панель
и каталог вкладки — обычные получатели. AD-группы и имена не заходивших приходят сразу; клики
«Кто из ЦА» не перезапрашивают панель.

## §2 Костыль выпадашки (заявка платформе 2026-09-14, прецедент — фильтр борда 59922)

- iframe sandbox="allow-scripts" размером с ячейку; до родителя — только postMessage
  `ECHARTS_UPDATE_DATA_URL {dataUrl}` (канал скриншотов → `img.echarts-plugin` рядом с iframe).
- Открыли → PNG 1×1 + байты маркера после IEND, выровненные по 3 байта: в base64 стоит
  `UEEtQ0EtREQtT04x` («PA-CA-DD-ON1»). Закрыли → чистый PNG. Шлём `{type, dataUrl, payload:{dataUrl}}`
  (форма сообщения восстановлена по заявке — поле дублируется на случай вложенного payload).
- CSS борда (`Лист Аудитория — актуальные файлы/9. CSS борда…`) — калька с рабочего CSS борда 59922 (скрин владельца 2026-09-25):
  overflow visible у .slice_container / .chart-container / .dashboard-chart; ЯКОРЬ — `#chart-id-<id>`
  (обёртка iframe внутри области чарта, не ячейка с заголовком — иначе прыжок на высоту заголовка);
  iframe absolute top/left 0, 100% × min(640px, 85vh), z-index 998, фон прозрачный. Строку сетки НЕ
  поднимаем (на 59922 не нужно). «Прозрачная ячейка» 59922 нам не нужна: у строки своя карточка.
  Красные «!» редактора CSS у :has — линтер Ace, не ошибка.
- Выпадашка — узел в body iframe, position:fixed, под кнопкой; max-height по innerHeight
  (пересчёт на resize, когда iframe вырос). Фон html/body/хоста — прозрачный на время открытия,
  overlay зажат в baseH (высота строки до открытия).
- Закрытие: клик внутри iframe мимо выпадашки (в т.ч. по прозрачной части поверх каталога), blur окна
  iframe (клик за пределами развёрнутого iframe), Esc. Клик внутри выпадашки помечается `e.__pacaDd`:
  пересборка отрывает цель от DOM, проверка предков ошиблась бы.
- Перезапуск скрипта при открытой выпадашке — сигнал повторяется (0 / 400 / 1500 мс): настоящий
  скриншот платформы мог затереть маркер.

## §3 Данные

pa_ca_dict фильтров не читает. Значения условий — те же, что сравнивают pa_aud_v2 / pa_body_aud
(путь ou() + « › », остальное как есть). Числа выпадашек — фасеты по штату (как в панели v4).
AD-группы — размер в штате (pa_adg_size), пересечение считает сервер.
Регресс: `check_aud.py` — справочник == штат; «в ЦА» строки == ЦА панели (± владельцы отчёта) на 5 наборах.

## §4 Пилюли условий (правка владельца 2026-09-25 по рендеру)
- Пусто — только название (без «все»). Одно значение — само значение, без названия (nonHQ, Блок 1,
  «Без руководителей»). Несколько — название + счётчик. × на выбранной пилюле снимает условие,
  клик по пилюле — выпадашка; в ней выбранные значения чипами с × над списком.
- Первое условие — «Управленческая структура». Слева — «Целевая аудитория» + статус (по правам /
  по условиям / не применено) + пояснение «настройка для углублённого анализа…».
- Нулевые значения НЕ показываем (правка владельца «нули не показываем»): значение/узел без людей под
  остальными условиями скрыт, кроме выбранного (и узлов на пути к нему) — чтобы галочку можно было снять. Перекрёстный пересчёт сверен на стенде в обе
  стороны (синтетика: HQ/IT развязаны с оргструктурой через intHash32).

## §5 AD-группы точно (2026-09-25, фидбек «группы не фильтруются — пишет без учёта групп»)
- pa_ca_dict: единица = (путь, спец., стрим, рук., HQ, IT, НАБОР AD-групп) — 7-е поле «номера групп через запятую»,
  номер = parent строки 'adg' (row_number по имени в pa_adg_size). Люди с одинаковыми атрибутами и группами —
  одна строка. Условие 'adg' в CA_KINDS: «хотя бы одна из выбранных» (как сервер); фасет групп = сотрудники
  группы под остальными условиями, нули скрыты. Старый датасет без 7-го поля → MODEL.adgExact=false, прежнее
  «без учёта групп». Регресс: check_aud «в ЦА» строки == ЦА панели на 3 наборах с ca_adg_f.
- Слово «штат» в интерфейсе заменено на «сотрудники с AD-логином» (штатные и ГПХ).

## §6 ОТКРЫТЫЕ ХВОСТЫ

- Форма postMessage не проверена на бою (стенд эмулирует родителя по заявке; CSS сверен со скрином 59922). Не раскрылось поверх — сверить с JS фильтра 59922 (`notifyOverlay`).
