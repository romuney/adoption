# pa-one — панель ЕДИНОГО листа (объединение «Использование» + «Охват ЦА»)

Точка восстановления: прочитать целиком, найти первый пункт плана ≠ DONE и продолжать с него.

## Задача (владелец, 2026-09-30)
Кейс: на первом листе хотят «динамику по IT-тимлидам» — это умеет только второй лист (строка ЦА),
про него не знают. Решение владельца: объединить листы в один. Делать в ОТДЕЛЬНОЙ папке
(`Единый лист — актуальные файлы/`): владелец соберёт всё на тестовом дашборде, проверит и только
потом заменит на боевом (отчётом уже пользуются). GP-параграфы тоже можно менять, но отдельно.

## Раскладка единого листа
1. Шапка pa-head (pa_head) — период + «Считать» + дата данных + ряд «Целевая аудитория» одним чартом
   (с 2026-09-30; прежние pa-strip и pa-ca-bar на едином листе не нужны).
2. Каталог (pa-reports-body, SQL с WITH_CA = true, датасет pa_body_one) — «Охват ЦА» в колонках, вкладка
   «Аудитория» (разрезы штата, клик → группа в панель).
3. Панель pa-one: KPI (5 первого листа + «Охват ЦА»), «Что видно», вкладки
   Динамика (+ блок охвата ЦА) · Календарь · Путь ЦА · Кто смотрит (режим: частота | ЦА) · Закрепляемость.

## Семантика ЦА на едином листе
- ЦА «по правам» (по умолчанию, условий нет): зрители НЕ сужаются. У человека флаг ca = действующий
  сотрудник (pa_staff) с правом хотя бы на один отчёт области. Охват = зрители из ЦА / размер ЦА.
  Доступ почти у всех (ЦА ≥ wideShare штата) — проценты охвата скрыты.
- ЦА «по условиям» (IT, тимлиды, подразделения…): ВСЁ на листе — про этих людей (каталог уже так делает):
  pa_people-часть считается только по логинам ЦА. «Вне ЦА заходили» — одним числом.

## Датасет pa_one (панель) — pa_people + ЦА
- Всё, что было в pa_people (total/freq/ctx/ts/cal/coh/area) — как было, но при ЦА по условиям evd
  сужен до логинов ЦА (тот же caset, что в каталоге).
- ОДИН упакованный список людей (section = list) — зрители ТЕКУЩЕГО периода; поля:
  логин · ФИО · id спец · id стрима · id стажа · рук · маска тек. окна · маска пред. окна · возраст 1-го визита ·
  просмотров · дней с визита · MAU · MAU пред. · в этом году · штат · доступ · в ЦА · id HQ · id IT.
  Специализация/стрим/стаж/HQ/IT — кодами из словаря (section = d) — сжатие (ответ в JSON Superset
  8,0 → ~3,5 МБ на весь Proteus). Разделители — как были (\t, \n).
- h — штат БЕЗ визитов в текущем периоде, свёрнут по (путь, спец, стрим, рук, HQ, IT): n · с доступом · в ЦА ·
  в ЦА и с доступом.
- n — поимённо люди ЦА без визитов в текущем периоде (≤ NAMES_MAX).
- acl — как роздан доступ (группы / поимённые).
- area-строка — как в pa_people (+ эхо flt, md, ds, kt) + скаляры ЦА в state-поле: staff, caMode, ca{…},
  reachPrev, regPrev, yr (ЦА с визитом в этом году), out (вне ЦА заходили — при условиях).

## v2 (2026-09-30, вечер): ответ из 5 колонок, скорость, связь с «Аудиторией» каталога
Запрос владельца: «после объединения работать стало хуже — хочется быстрее».
- **Почему ответ был тяжёлым.** Superset отдаёт JSON записями: имена колонок повторяются в КАЖДОЙ строке
  (35 колонок × 1716 строк), кириллица при ensure_ascii — `\uXXXX`, 6 байт на букву.
- **Формат v2 — 5 колонок `section · g · k · parent · n`** (как у pa_head и каталога). Строки секции — в k через
  `\n`, поля — через `|`. Кириллица сжата: макрос `cz` (SQL) оборачивает отрезки кириллицы с пробелами в обратные
  кавычки и переводит translateUTF8 по таблицам CYR→TGT (буква → 1 ASCII-символ); `unz()` в JS разворачивает.
  Экранирование: `~~` `~p`=| `~c`=^ `~b`=`. В TGT есть «0123456789» — метка id в Проверках 777777, не 12345.
- **Секции v2**: area (n = kt) · md · total (20 полей) · ctx (только users > 0) · list (строка человека `pln`
  собрана ДО arrayJoin ролей) · ts/cal (из tc: sumMap по bitPositionsToArray(bitAnd(msk, CUR))) · coh · d (одна
  строка на словарь) · h/n (путь cz(op)) · acl (одна строка) · flt · sj (+ `"aud":{…}` — группа из каталога).
- **Приёмы CH 24**: transform() с константными массивами вместо indexOf по массиву-скаляру (тот копировался на
  строку: в 20 раз медленнее на словаре в 800 значений); translate вместо regexp; прямая граница `log_dttm >= …`
  для отсечения партиций; bitTest падает на позиции > 63 даже внутри ложного AND — `least(fd_k, 63)`; у КАЖДОГО
  плеча UNION явные алиасы (старый анализатор схлопывал одинаковые `''`); `{#- -#}` склеивает токены
  (`1AND`, `xWHERE`) — у места склейки `{# #}`.
- **Группа из «Аудитории» каталога** (aud_org_f / aud_spec_f / aud_stream_f / aud_hq_f / aud_it_f / aud_head_f):
  работает как ЦА по условиям (`custom = … or auon`, условия в cond()), эхо — в flt и sj.aud; заголовок панели
  «ЦА: …» = условия шапки + группа (caCondText). Сверено: люди и размер ЦА == строка группы в каталоге (check_one §6).
- **Сегмент ЦА — только список** (владелец 2026-09-30, отменил эмит seg_f): клик по «дошли / не заходили / вне ЦА»
  фильтрует список панели, каталог не трогает. В SQL/JS каталога seg_f остался запасом (никто не шлёт).
- **Разрезы для вкладки «Аудитория» каталога при выбранной области** — секция `aa` (только when have): зрители периода
  области (без условий группы aud_*, с условиями строки ЦА) × pa_staff, те же разрезы/правила, что aud каталога.
  Каталог свой выбор не видит (самовлияние выключено) — панель шлёт PA_AUD {key: mode_param+sel_f из эха, rows};
  каталог по PA_AUD_ASK при монтаже просит переслать. check_one §10; стенд big +0,04–0,1 с.
- **«Вне ЦА» поимённо при ЦА по условиям** — секция `lo` (evo: зрители периода NOT IN caset, те же пары/владельцы/
  срез, что evd; po: строки как у list через общий макрос plnx(inca = 0), ≤ OUT_MAX = 20 000 самых активных);
  ca_out = count() по evo — число и список из одного набора. JS: MODEL.outList — только в режиме «по ЦА»
  (baseList, caSegs, groupAgg → колонка «Вне ЦА»); KPI, частота, totals — про людей ЦА (tot.out = скаляр).
  Стенд big: IT-тимлиды 0,92 → 1,20 с, 0,21 → 1,56 МБ; по правам без изменений. check_one §9.
- **«уволен» → «увол.»** (серый `.rflag.fired`, в выгрузке «Увол.»): логина нет среди действующих — кто
  инициатор, не различаем. «Не в штате» владелец тоже отверг: у нас не только штатные (база — штатные и ГПХ).
- **JS**: SWAR `bits()`, ленивый fioOf, `p.last` (дней от md) вместо last_dt (дата — lastDate(p) в выгрузке),
  ширина SVG/высоты — в state (без пересчёта на каждый render).
- **Замеры (стенд big, медиана 7 прогонов, было → стало)**: весь Proteus 1,24 → 1,15 с, 5,28 → 3,01 МБ;
  месяц 1,45 → 1,27 с, 5,21 → 2,80 МБ; один отчёт 0,67 → 0,69 с, 2,58 → 0,92 МБ; IT-тимлиды 1,07 → 1,01 с,
  0,92 → 0,21 МБ. Браузер: открытие 342 → 207 мс, перерисовка на новых данных 322 → 196 мс, клики в 1,5–2 раза
  быстрее. HTML всех вкладок до/после — байт в байт (кроме намеренных правок).
- **Проверки**: check_one §1–§8 (§4 — старый анализатор и prefer_column_name_to_alias с нормализацией порядка
  строк в ячейке; §8 — Проверки SQL Lab == текущие шаблоны, `--rebuild` пересобирает); syncall

## Сортировка в несколько уровней (2026-10-09, ночь-10)
- Помощник (одинаков в обоих виджетах): sortLevels(sc, k) · sortClick(sc, k, col, shift, defDir) · sortRank · sortMark ·
  SORT_NOTE; уровни после первого — sc.then [{c, dir}], SORT_MAX 3; k — 'col' (каталог) / 'key' (панель).
- Сравнение — по уровням по очереди, затем прежний добор (пользователи, дни…). Пустые — вниз на любом уровне (панель).
- Каталог: «Ритм» не последним уровнем сравнивается только частотой (без твёрдости) — иначе второй уровень не работал.
