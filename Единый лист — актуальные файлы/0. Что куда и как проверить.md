# Единый лист — актуальные файлы

Один лист вместо двух («Использование» + «Охват ЦА»). Всё, что было на втором листе, теперь на первом:
строка «Целевая аудитория» под шапкой, «Охват ЦА» в каталоге и в KPI, охват в динамике, вкладка «Путь ЦА»,
«Кто смотрит» с разбивкой по частоте или по ЦА. Кейс «динамика по IT-тимлидам»: в строке ЦА выбрать IT и
«Руководители» → «Применить» — каталог, KPI, динамика, календарь, «Кто смотрит» и закрепляемость считаются
только по этим людям.

Здесь по файлу на объект Proteus. Когда что-то меняется, я правлю файл здесь и пишу «замени из файла N».

Итого нового — **один датасет и один чарт** (файлы 9 и 10). Остальное уже работает в бою: для тестового
дашборда можно взять существующие датасеты (`pa_strip`, `pa_ca_dict`, `pa_body_aud`) — SQL у них тот же.

## Раскладка листа

1. **Шапка** — во всю ширину (как сейчас).
2. **Строка «Целевая аудитория»** — сразу под шапкой, во всю ширину, высота ~64 px (одна строка сетки).
3. **Каталог** (~38 % слева) и **панель «Аудитория»** (~62 % справа).

## Панель — что в ней

- KPI: Пользователей · Просмотров · Новых · Постоянных · MAU · **Охват ЦА** (доля ЦА, заходившая за период;
  при доступе «почти у всех» процент скрыт — сузьте ЦА условиями).
- Вкладки: **Динамика** (нижний график: Всего · На пользователя · **Охват ЦА**) · **Календарь** · **Путь ЦА**
  (кого считаем ЦА + воронка «доступ → открыли → вернулись → регулярно») · **Кто смотрит** (переключатель
  «Разбивка: по частоте | по целевой аудитории»; во втором режиме — «дошли / не заходили / вне ЦА», группы с
  охватом, поимённо не заходившие) · **Закрепляемость**.
- ЦА **по правам** (по умолчанию) зрителей не сужает — только показывает охват. ЦА **по условиям** — вся панель
  и каталог про этих людей; в заголовке панели «ЦА: …».

## Шаг 1. Тестовый дашборд (боевой отчёт не трогаем)

1. **SQL Lab** (база CROSS): прогнать `Проверки/SQL Lab — панель, весь Proteus.sql`, `… один отчёт.sql`
   (поставьте id), `… ЦА IT-тимлиды.sql` и `… каталог.sql`. Всё зелёное — пришли время первого прогона каждого.
   Красное — стоп, пришли текст ошибки целиком.
2. **Датасет pa_one** = файл 9 → Save → «Синхронизировать колонки» (в нём 35 колонок, новые у pa_people:
   `ca_prev`, `ca_regprev`, `ca_yr`, `ca_out`, `state_j`).
3. Новый дашборд, лист по раскладке выше. Чарты `react_sanbbox`: шапка (датасет pa_strip, JS = файл 4),
   строка ЦА (pa_ca_dict, JS = 6), каталог (pa_body_aud или pa_body_one из файла 7, JS = 8),
   панель (pa_one, JS = 10). «Измерения» — все поля; лимиты строк — из таблицы.
4. **CSS** = файл 11 в конец CSS тестового дашборда: `000000` → id чарта строки ЦА, `111111` → id чарта шапки
   (во всех местах). Блок «Вкладки листов» на одном листе не нужен — можно не вставлять.
5. **Кросс-фильтры** — по таблице выше.

### Проверка на тестовом дашборде
- Без выбора: 6 KPI, в «Охват ЦА» — процент или «доступ почти у всех».
- Клик по отчёту в каталоге → панель приглушается «Пересчитываем…» и показывает этот отчёт.
- Строка ЦА: IT + Руководители → «Применить» → каталог и панель сужаются; в заголовке панели «ЦА: IT · руководители»;
  «Пользователей» в KPI = ИТОГО каталога.
- «Кто смотрит» → «По целевой аудитории» → полоса «дошли / не заходили / вне ЦА»; клик по «не заходили» —
  поимённо люди ЦА без визитов.
- «Динамика» → внизу «Охват ЦА» → линии охвата.
- Числа без ЦА — те же, что на боевом листе «Использование» (датасет сверен с pa_people на стенде строка в строку).

## Шаг 2. Перенос на боевой отчёт (после проверки)

1. Лист «Использование»: чарт правой панели → датасет **pa_one**, JS = файл 10 (или новый чарт вместо старого).
2. Каталог первого листа → датасет **pa_body_aud** (или SQL из файла 7 в его датасет), JS не меняется.
3. Строку «Целевая аудитория» перенести со второго листа на первый под шапку (тот же чарт — id не изменится,
   CSS уже стоит).
4. Кросс-фильтры — по таблице выше.
5. Лист «Охват ЦА» удалить; старые датасеты `pa_people` / `pa_aud_v2` — после недели без жалоб.
