# Единый лист — актуальные файлы

Один лист вместо двух («Использование» + «Охват ЦА»). Всё, что было на втором листе, теперь на первом:
строка «Целевая аудитория» под шапкой, «Охват ЦА» в каталоге и в KPI, охват в динамике, вкладка «Путь ЦА»,
«Кто смотрит» с разбивкой по частоте или по ЦА. Кейс «динамика по IT-тимлидам»: в шапке, в ряду «Целевая
аудитория», выбрать IT и «Руководители» → «Применить» — каталог, KPI, динамика, календарь, «Кто смотрит» и
закрепляемость считаются только по этим людям.

**Борд — три чарта** (2026-09-30): **шапка** во всю ширину (период · «Считать» · дата данных, ниже — ряд
«Целевая аудитория»), под ней **каталог** слева и **панель «Аудитория»** справа. Прежние отдельные чарты
«Шапка» (pa_strip) и «Целевая аудитория» (pa_ca_dict) заменены одной шапкой: один датасет, один JS.

Здесь по файлу на объект Proteus. Когда что-то меняется, я правлю файл здесь и пишу «замени из файла N».

Нового — **два датасета и два чарта**: шапка (файлы 3–4) и панель (7–8). Каталог уже работает в бою: для
тестового дашборда можно взять существующий датасет `pa_body_aud` — SQL тот же.

## Раскладка листа

1. **Шапка** — во всю ширину, высота ~112 px (два ряда: период и «Считать»; «Целевая аудитория»).
2. **Каталог** (~38 % слева) и **панель «Аудитория»** (~62 % справа).

Выпадашки условий ЦА и подсказки переключателей раскрываются поверх каталога и панели (CSS из файла 9).

## Панель — что в ней

- KPI: Пользователей · Просмотров · Новых · Постоянных · MAU · **Охват ЦА** (доля ЦА, заходившая за период;
  при доступе «почти у всех» процент скрыт — сузьте ЦА условиями).
- Вкладки: **Динамика** (нижний график: Всего · На пользователя · **Охват ЦА**) · **Календарь** · **Путь ЦА**
  (кого считаем ЦА + воронка «доступ → открыли → вернулись → регулярно») · **Кто смотрит** (переключатель
  «Разбивка: по частоте | по целевой аудитории»; во втором режиме — «дошли / не заходили / вне ЦА», группы с
  охватом, поимённо не заходившие) · **Закрепляемость**.
- ЦА **по правам** (по умолчанию) зрителей не сужает — только показывает охват. ЦА **по условиям** — вся панель
  и каталог про этих людей; в заголовке панели «ЦА: …».

## Настройки чартов

Все чарты — eCharts (`react_sanbbox`), в «Измерения» — **все поля датасета**.

| Чарт | Датасет | Лимит строк |

| Шапка | **pa_head** | 50 000 |
| Каталог | pa_body_one (или pa_body_aud) | 50 000 |
| Аудитория (панель) | **pa_one** — все **35** полей | 50 000 |

## Кросс-фильтры (самовлияние у всех выключено)

| Источник | Влияет на |
|---|---|
| Шапка | Каталог, Аудитория |
| Каталог | Аудитория |
| Аудитория | Каталог |

На шапку не влияет никто: её датасет фильтров не читает (дата данных и справочник ЦА — одни на всех).

## Шаг 1. Тестовый дашборд (боевой отчёт не трогаем)

1. **SQL Lab** (база CROSS): прогнать `Проверки/SQL Lab — панель, весь Proteus.sql`, `… один отчёт.sql`
   (поставьте id), `… ЦА IT-тимлиды.sql`, `… каталог.sql` и `… шапка.sql`. Всё зелёное — пришли время первого прогона каждого.
   Красное — стоп, пришли текст ошибки целиком.
2. **Датасет pa_head** = файл 3 → Save → «Синхронизировать колонки» (5 колонок: section, g, k, parent, n —
   как у pa_ca_dict).
3. **Датасет pa_one** = файл 7 → Save → «Синхронизировать колонки» (в нём 35 колонок, новые у pa_people:
   `ca_prev`, `ca_regprev`, `ca_yr`, `ca_out`, `state_j`).
4. Новый дашборд, три чарта по раскладке выше, все `react_sanbbox`: шапка (pa_head, JS = файл 4),
   каталог (pa_body_aud или pa_body_one из файла 5, JS = 6), панель (pa_one, JS = 8).
   «Измерения» — все поля; лимиты строк — из таблицы.
5. **CSS** = файл 9 в конец CSS тестового дашборда: `000000` → id чарта шапки (во всех местах, оба блока).
   Блок «Вкладки листов» на одном листе не нужен — можно не вставлять.
6. **Кросс-фильтры** — по таблице выше.

### Проверка на тестовом дашборде
- Шапка: справа «данные на ДД.ММ» с зелёной точкой (вчера). Наведение на «Без владельцев» — подсказка
  поверх каталога; клик по «Управленческая структура» — выпадашка поверх каталога и панели, ничего не прыгает.
- Без выбора: 6 KPI, в «Охват ЦА» — процент или «доступ почти у всех».
- Клик по отчёту в каталоге → панель приглушается «Пересчитываем…» и показывает этот отчёт.
- Ряд «Целевая аудитория»: IT + Руководители → «Применить» → каталог и панель сужаются; в заголовке панели «ЦА: IT · руководители»;
  «Пользователей» в KPI = ИТОГО каталога.
- «Кто смотрит» → «По целевой аудитории» → полоса «дошли / не заходили / вне ЦА»; клик по «не заходили» —
  поимённо люди ЦА без визитов.
- «Динамика» → внизу «Охват ЦА» → линии охвата.
- Числа без ЦА — те же, что на боевом листе «Использование» (датасет сверен с pa_people на стенде строка в строку).

## Шаг 2. Перенос на боевой отчёт (после проверки)

1. Лист «Использование»: чарт шапки → датасет **pa_head**, JS = файл 4 (или новый чарт вместо старого —
   тогда в CSS борда поменять id шапки).
2. Чарт правой панели → датасет **pa_one**, JS = файл 8 (или новый чарт вместо старого).
3. Каталог → датасет **pa_body_aud** (или SQL из файла 5 в его датасет), JS не меняется.
4. CSS борда: оба блока (выпадашки ЦА и подсказки шапки) — на id чарта шапки; блок со старым id строки ЦА
   убрать. Кросс-фильтры — по таблице выше.
5. Лист «Охват ЦА» (со строкой ЦА) удалить; старые датасеты `pa_strip` / `pa_ca_dict` / `pa_people` /
   `pa_aud_v2` — после недели без жалоб.
