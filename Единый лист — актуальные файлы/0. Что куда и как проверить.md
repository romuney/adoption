# Единый лист — актуальные файлы

Один лист вместо двух («Использование» + «Охват ЦА»). Всё, что было на втором листе, теперь на первом:
строка «Целевая аудитория» под шапкой, «Охват ЦА» в каталоге и в KPI, охват в динамике, вкладка «Путь ЦА»,
«Кто смотрит» с разбивкой по частоте или по ЦА. Кейс «динамика по IT-тимлидам»: в шапке, в ряду «Целевая
аудитория», выбрать IT и «Руководители» → «Применить» — каталог, KPI, динамика, календарь, «Кто смотрит» и
закрепляемость считаются только по этим людям.

**Борд — три чарта**: **шапка** во всю ширину (период · «Считать» · дата данных, ниже — ряд «Целевая
аудитория»), под ней **каталог** слева и **панель «Аудитория»** справа.

Здесь по файлу на объект Proteus. Когда что-то меняется, я правлю файл здесь и пишу «замени из файла N».

   учитывают шапку (период, опции), ЦА по условиям и выбор в «Кто смотрит».
   **Клик по группе** → панель справа показывает эту группу людей: охват, динамику, календарь, «Кто смотрит»,

   крестиком в пилюле каталога.
   **Если в «Отчётах», «Коллекциях» или «Владельцах» что-то выбрано**, вкладка показывает только группы, которые
   это смотрели за период (пометка «по выбору в каталоге»): «Польз.», «Охват», «Пост.» — по выбранному, «Сотр.» —
   вся группа. Клик по такой группе больше не даёт пустую панель. Эти числа считает датасет панели (секция aa) и
   передаёт каталогу; пока панель пересчитывается — «Считаем аудиторию выбранных отчётов…».
2. **Каталог не медленнее.** Сам SQL из-за разрезов «Аудитории» дольше на ~0,1 с, но ответ стал в 5 раз
   легче (5,9 → 1,1 МБ): Superset упаковывает его на ~0,3 с быстрее, по сети идёт на 4,8 МБ меньше.
   В сумме каталог не медленнее прежнего, а скорее быстрее. Цифры — в конце.
3. **Панель быстрее**: ответ в 2–4 раза легче, открытие и перерисовка ~в 1,6 раза быстрее, SQL не медленнее.
   Выглядит и считает так же: на стенде числа сверены с прежними датасетами строка в строку.
4. **«Кто смотрит» → «по целевой аудитории»: клик по «дошли / не заходили / вне ЦА» — только список людей**
   в панели, каталог не меняется. **«Вне ЦА» теперь поимённо и при ЦА по условиям** (IT, тимлиды, группа из
   «Аудитории» каталога): кто заходил за период, но под условия не подходит. Раньше при условиях было только
   число. Если таких больше 20 000 — в списке 20 000 самых активных (подсказка на полосе это скажет).
   В группировке (подразделения и т. п.) у групп появляется колонка «Вне ЦА».
5. **«уволен» → «увол.»** (серым, не красным), в выгрузке колонка «Увол.». Сокращение не говорит, ушёл
   человек сам или его уволили, — данные этого и не различают: знаем только, что логина нет среди действующих
   сотрудников (штатные и ГПХ с AD-логином).

## Раскладка листа

1. **Шапка** — во всю ширину, высота ~112 px (два ряда: период и «Считать»; «Целевая аудитория»).
2. **Каталог** (~38 % слева) и **панель «Аудитория»** (~62 % справа).

Выпадашки условий ЦА и подсказки переключателей раскрываются поверх каталога и панели (CSS из файла 9).

## Панель — что в ней

- KPI: Пользователей · Просмотров · Новых · Постоянных · MAU · **Охват ЦА** (доля ЦА, заходившая за период;
  при доступе «почти у всех» процент скрыт — сузьте ЦА условиями).
- Вкладки: **Динамика** (нижний график: Всего · На пользователя · **Охват ЦА**) · **Календарь** · **Путь ЦА**
  (кого считаем ЦА + воронка «доступ → открыли → вернулись → регулярно») · **Кто смотрит** (переключатель
  «Разбивка: по частоте | по целевой аудитории»; во втором режиме — «дошли / не заходили / вне ЦА», группы с
  охватом, поимённо не заходившие) · **Закрепляемость**.
- ЦА **по правам** (по умолчанию) зрителей не сужает — только показывает охват. ЦА **по условиям** (из шапки
  или группа из вкладки «Аудитория» каталога) — вся панель про этих людей; в заголовке панели «ЦА: …».
