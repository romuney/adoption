# Выкатка на прод — по шагам

Здесь — всё, что накопилось с пятницы 23.10:

- **ускорение через GP**: 3 новых gp-параграфа (9 витрин) + выгрузка, SQL 3, 5, 7 на них;
- **вкладки и большой экран**: JS 6, 8 (вкладки не прыгают, «Кто смотрит» во всю ширину, строк в каталоге по высоте).

Все файлы этой папки — полный комплект листа. Рабочая версия до этих правок лежит рядом, в папке
«Единый лист — актуальные файлы» (и на GitHub, ветка `unified-sheet-pre-gp`). Откат — файлы оттуда.

Порядок сделан так, чтобы на каждом шаге можно было остановиться, и ничего не сломалось:

1. GP — витрины добавляются рядом со старыми, борды их пока не читают.
2. Проверка витрин на боевых данных.
3. Тестовый дашборд 61364.
4. Боевой дашборд 13896.

Любое красное — стоп. Пришли текст ошибки целиком (или скрин) и номер шага.

## Этап 1. GP — витрины (Helicopter, нода 844437). Борды пока не меняются

Новые витрины добавляются рядом со старыми: ни один датасет их ещё не читает. Если что-то пойдёт не так, борды
работают как раньше.

**1.1. Три новых gp-параграфа — в самый конец ноды**, после всех существующих, в том числе после python-параграфа
выгрузки. Так, если новый параграф упадёт, старые витрины к этому моменту уже выгружены, и борд получит свежие данные как
обычно. Каждый параграф — отдельный файл этой папки: открыл, Ctrl+A, скопировал, вставил в новый gp-параграф целиком.

| Параграф (имя — любое, например) | Файл | Что строит |
|---|---|---|
| PA · ускорение 1/3 — люди, коды, дата свежести | `1a. GP — новый параграф 1 из 3 (…).sql` | `pa_md`, `pa_dict`, `pa_viewer`, `pa_staffx` (+ времянка `pa_acc_any`) |
| PA · ускорение 2/3 — календари по дням | `1b. GP — новый параграф 2 из 3 (…).sql` | `pa_dash_day`, `pa_all_day` |
| PA · ускорение 3/3 — каталог | `1c. GP — новый параграф 3 из 3 (…).sql` | `pa_cat_rep`, `pa_cat_grp`, `pa_cat_aud` |

Таблицы создаются **без схемы**, как `collection_array` и `period_agg` в этой же ноде: их забирает выгрузка, борды GP
не читают. Служебная `pa_acc_any` — `temp`-таблица внутри параграфа 1a. В параграфе 1a длинный список чисел внутри
`array[…]` — это коды знаков препинания (правило «уровень оргструктуры из одних „-“, „—“, „…“ — пусто», ровно как в
ClickHouse). Вставляй целиком. Существующие параграфы ноды не трогай.

**1.2. Выгрузка — четвёртый новый параграф, python, после трёх gp.** Текст — файл
`2a. Python — выгрузка новых витрин (отдельный параграф).py` целиком. Существующий параграф выгрузки не трогай.

**1.3. Запусти ноду целиком.** Запомни, сколько она шла раньше и сколько теперь: новые параграфы прибавят время, и
мне важно знать, сколько. Если упал один из новых параграфов — пришли текст ошибки и его номер. Борды при этом
работают как вчера.

**1.4. Проверка витрин — файл 13 в SQL Lab** (база, где лежат `prod_proteus.pa_*`). Вставь файл целиком, нажми «Run».
Должно быть 12 строк, в колонке `ok` — везде 1. Каждая строка сравнивает витрину с тем, что датасеты сейчас
считают сами, на боевых данных.

- Хоть один 0 — **дальше не идём**. Пришли таблицу целиком.
- Все единицы — можно переходить к этапу 2.

**1.5. (По желанию) замер одним запросом:** `Проверки/0. ЗАМЕР БОЯ — один запрос (запустить только его).sql` из этой
папки → SQL Lab → «Run». Пришли время выполнения — сравню с прошлым замером.

### Проверка на тестовом

1. **Числа «до» и «после» совпадают** (скрины из 0.2): ИТОГО каталога, KPI панели, клик по верхнему отчёту,

2. **Периоды:** 20 недель, 12 месяцев, 8 кварталов, «Свой» (любые даты) — каталог и панель считаются, ошибок нет.
3. **Переключатели «Считать»:** выключи и включи по очереди «Опубликованные», «Актуальные», «Без владельцев» —
   ИТОГО каталога меняется, ошибок нет.
4. **Клик по отчёту:** KPI и «Динамика» — сразу. Вкладки «Кто смотрит» / «Путь ЦА» пока догружаются — под
   названием три точки, ширина вкладок не меняется.
5. **ЦА:** в строке «Целевая аудитория» IT + Руководители → «Применить». Каталог и панель пересчитались, в заголовке
   панели «ЦА: …».
6. **Людская шина:** «Кто смотрит» → «По частоте» → «1 день» — каталог сузился. Повторный клик — снят.
7. **Вкладка «Аудитория» каталога:** клик по группе — панель «ЦА: <группа>».
8. **Большой экран** (если есть монитор): «Кто смотрит» — во всю ширину, внизу каталога «Показано 1–N», N ≥ 20.
9. **Скорость.** Открой борд, смени период, кликни отчёт — должно быть заметно быстрее, чем на скринах «до». Если не

Что-то не так — откат: SQL, JS и CSS из 0.1 обратно, Save, Cmd+Shift+R. Витрины GP при этом можно не трогать: старым
SQL они не мешают.

## Каждый день после выкатки

Витрины обновляет та же нода раз в сутки, вместе с остальными. Если нода стала красной на одном из новых
параграфов, борд покажет вчерашние числа каталога при сегодняшних числах панели. Тогда перезапусти ноду, а не
получится — пришли ошибку. Проверка в любой момент — файл 13: строка 01 покажет, если дата витрин отстала от
`pa_pair`.

## Откат целиком

1. SQL, JS и CSS — из сохранённого в 0.1 (или из папки «Единый лист — актуальные файлы»). Save, Cmd+Shift+R.
