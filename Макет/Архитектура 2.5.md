# Архитектура 2.5 — две зеркальные вкладки с каталогами

Source of truth макета: какой блок экрана на каком датасете живёт, какие
эмит/приём связывают блоки, что считается в браузере, а что уходит в SQL.
Читается вместе с `index.html` и `assets/app.js`. Версия 2.5 от 2026-09-21
(вечер-2): 2.4 + раунд владельца по двунаправленной связке каталог ⇄ «Кто
смотрит»: свиток сертифицированных убран, клик по группе и по ЧЕЛОВЕКУ —
людская шина с семантикой каталога (переключает / Shift накапливает),
список себя не сужает — держит контекст и подсвечивает выбор.
(2.4: ось-календарь, пилюльки-пересчёт, контекстные чипы; 2.3: поимённый
«Кто смотрит» с деревом групп слева; 2.2: вкладки симметричны, у каждой
свой каталог.)

## Суть

**Вкладка «Отчёты»**: каталог слева (отчёты · коллекции · владельцы,
компактная подшапка у левого края) — клик по строке задаёт «область»:
обычный клик ПЕРЕКЛЮЧАЕТ выбор на строку, повторный клик по единственной
выбранной снимает выбор, **Shift+клик накапливает**. Правая панель
переключается: **Динамика ⇄ Кто смотрит** (шапка — одна строка, как у
каталога).

**Динамика**: столбики-стек, легенда — кликабельные пилюльки над
графиком (гасят ступень С ПЕРЕСЧЁТОМ стека), ось X — «календарь» (метка
на каждой точке, второй ряд — смена месяца/года, смена — жирная).

**«Кто смотрит»** — поимённый список зрителей области: сигаретка частоты
с процентами, тулбар (группировка и настройки слева, счётчик и
сворачивание справа), дерево групп при группировке (при «Департаменте» —
двухуровневое: блок → департамент → люди). Настройки списка локальные:
«только руководители», исключённые логины.

**Клик по строке дерева — ЛЮДСКАЯ ШИНА, как в BI-паттерне кросс-фильтров
(источник себя не фильтрует)**:

- кликают СТРОКА группы (блок/департамент/разрез) и СТРОКА ЧЕЛОВЕКА —
  вся строка, не подчёркнутое имя;
- семантика выбора — как у каталога: клик переключает условие разреза,
  **Shift+клик накапливает**, повторный клик по единственной — снимает;
  между разрезами условия складываются по И (блок ∩ человек), внутри
  разреза — по ИЛИ (два блока = объединение публики);
- сужаются КАТАЛОГИ ОБЕИХ вкладок и динамика ⟳ — «что смотрит розница»
  видно в каталоге с метриками;
- сам список остаётся на месте (принцип сигаретки: селектор держит
  контекст): выбранная строка подсвечивается (синий фон + левая полоса),
  группы без людей текущей выборки ГАСНУТ (grp-dim), но не исчезают —
  по ним можно переключить выбор; группы с людьми — вверх, пустые — вниз;
- счётчик тулбара показывает «N человек из M» (N — текущая выборка,
  сходимость с KPI сохраняется: содержимое списка шина-калибровано) и
  «выбрано: K» — число активных людских условий;
- числа дерева — КОНТЕКСТНЫЕ (люди области без людской шины): «в
  области», «доля области», при расхождении — «в текущей выборке» в
  подсказке.

**Активные условия — контекстной строкой чипов у контента** (под «Что
видно в данных», над каталогом и динамикой). Чип человека подписан ФИО,
два и более — «Люди: N».

**Опции полоски — три свитка**: только опубликованные, только актуальные,
исключить владельцев. Свиток «только сертифицированные» УБРАН (раунд
2.5): сертификация остаётся бейджем ✓ в строках каталога, фильтром не
служит — двунаправленная связка каталог ⇄ «Кто смотрит» закрывает сценарий
без него.

**Вкладка «Аудитория»** — зеркало «Отчётов» про adoption: свой каталог,
шесть KPI (включая Adoption за год), панель ЦА + воронка, полноширинная
динамика охвата, «Кто из целевой аудитории» в форме «Кто смотрит».

## Правило без дублей (в рамках вкладки)

| Список | Единственное место |
|---|---|
| Отчёты, коллекции, владельцы | каталог вкладки (у «Отчётов» и «Аудитории» — два независимых руля одного списка) |
| Людские разрезы | «Кто смотрит» (группировка поимённого списка) и «Кто из ЦА» (сводная с охватом) |
| Поимённые списки | «Кто смотрит» и «Кто из ЦА → Поимённо» |
| Корзины частоты | только «Кто смотрит» (сигаретка сверху панели) |
| Активные условия | одна строка чипов у контента (полоска сверху чиста) |
| Когорты | вкладка «Отчёты», низ |

## Две шины кросс-фильтров

| | Отчётная шина | Людская шина |
|---|---|---|
| Кто пишет | каталог вкладки (клик — переключение, Shift — накопление) | «Кто смотрит»: клик по строке группы ИЛИ человека (та же семантика клика) |
| Кто читает | KPI, наблюдения, динамика, «Кто смотрит», когорты — своей вкладки | каталоги ОБЕИХ вкладок, динамика (куб перезапрашивается ⟳) |
| Кто НЕ читает | сам каталог (самовлияние выключено, подсветка клиентская) | сама панель «Кто смотрит»: контент калибруется числами (см. ниже), но дерево держит контекст и не схлопывается |
| В бою | эмит `mode_param` + `sel_f` | люди-фильтры куба `lvl3_f, lvl4_f, spec_f, stream_f, adg_f, heads_f` **+ логин** (новое требование 2.5 к кубу: клик по человеку) |
| Скорость | 0 с | цель ≤2 с (куб v6 на предагрегатах, замер у владельца) |

Числовая сходимость: содержимое списка (= то, что в «N человек из M» и
в сигаретке) считается по шина-калиброванной области — совпадает с KPI
пользователей. Контекст дерева (счётчики групп) — по области без шины,
поэтому при активной шине сумма групп может быть больше списка: это
объяснено в подсказках («в области» / «в текущей выборке»).

## Раскладка на чарты и вкладки Proteus

Вкладки борда Proteus — бесплатный верхний уровень. Правило: **в один
чарт — то, что должно пересчитываться мгновенно от смены разреза (один
ответ куба, клиент); отдельными чартами — то, что слушает эмит выбора и
может себе позволить ⟳.**

| Блок экрана | Чарт | Почему |
|---|---|---|
| Каталог + KPI + наблюдения + динамика + частота | тело (один чарт на кубе) | смена подшапки, сортировка, «Динамика⇄Кто смотрит», пилюльки, группировка поимённо — клиентские |
| «Кто смотрит» (поимённо + дерево) | на выбор: внутри тела ИЛИ чарт-приёмник | как приёмник слушает эмит каталога; писатель людской шины (группы, люди, Shift-набор) |
| Закрепляемость | отдельный чарт `pa_cohorts` (уже так) | приёмник обеих шин |
| Вкладка «Аудитория»: каталог + KPI/adoption + воронка + «Кто из ЦА» | свой чарт-панель (расширение поставленной панели pa-audience) | слушает СВОЙ выбор каталога |
| Динамика охвата | отдельный чарт | приёмник эмита области |

## Что считается где

- **SQL**: сырые агрегаты (область × период, область × атрибут, когорта ×
  возраст, freq-корзины области). Поимённый список — ORDER BY разреза +
  серверная пагинация. Исключённые логины и «только руководители» — фильтр
  сессий. Людская шина по человеку — фильтр по логину (требование к кубу
  v6: логин в людской маске; в v5.1 колонки логина нет).
- **JS**: доли, дельты, дедуп микс-выбора, наблюдения по порогам,
  сегменты поведения, дерево группировки (контекст + гашение + подсветка
  выбора), гашение пилюлек с пересчётом, ось периодов «календарь».

## Мок → прод: соответствие состояний

| Состояние макета | В проде |
|---|---|
| период d/w/m/q | `period_param` куба |
| свитки опций | `pub_f/act_f/exc_f` (cert_f больше нет) |
| клик по строке каталога (Shift — мультивыбор) | эмит `mode_param`+`sel_f`; тело не перечитывает себя |
| клик по строке группы/человека «Кто смотрит» | люди-фильтры куба: оба каталога + динамика ⟳ (для человека нужна логин-колонка) |
| Shift+клик — накопление, повторный — снятие | накопление маски значения в свой разрез `*_f` |
| подсветка выбора и гашение групп | клиент: список не перечитывает себя |
| freq-корзина (сигаретка) | эмит корзины в ту же людскую шину |
| пилюльки динамики | клиент: пересчёт стека от оставшихся |
| настройки «Кто смотрит» | SQL-фильтр сессий (`is_head`, логины) |
| Adoption за год | годовое окно в SQL аудитории (с 1 января) |
| воронка, «не заходили», ФИО | ждут выгрузки прав и решения о пагинации |

## Хвосты (сознательно не сделано в 2.5)

  умеет pickable).
