# Обновление 2026-09-19: панель «Аудитория»

## Что это и зачем

Пятый виджет дашборда — **панель «Аудитория»**: объединённый экран «первая
история + анализ ЦА» из макета. Показывает, КТО смотрит текущую область:
шапка (область + период), 5 KPI (зрители / просмотры / новые / регулярные /
разовые, с дельтами к прошлому периоду), раскрывашка «Что видно в данных»
и таблица «Охват по разрезу» (УС-3, УС-4 деревом, специализация, стрим,
AD-группы топ-40, тим-лиды; при люди-разрезе области — ещё «Отчёты области»,
топ-25) с полосами долей и строкой ИТОГО.

Почему панель, а не вкладка внутри тела: самовлияние тела выключено ещё в v5,
куб тела sel-маску не читает — зрители выбранного отчёта вкладке взять
неоткуда. Панель — приёмник ТОГО ЖЕ эмита выбора (mode_param + sel_f), что
и закрепляемость: клик по строке каталога тела меняет область, панель
пересчитывает аудиторию ЛЁГКИМ запросом по предагрегатам
(pa_evd_day × pa_emp_attrs × pa_dash_meta), куб тела не трогает.

Обратные клики: строка разреза в таблице → эмит cut:* (сузится закрепляемость);
отчёт из «Отчётов области» → эмит report (закрепляемость по этому отчёту).
Сама панель и тело при этих кликах НЕ перерисовываются — так задумано.

## Шаг 1 — проверить SQL в SQL Lab

SQL Lab, база CROSS/prod_proteus. Джиню SQL Lab не рендерит, поэтому файл 1 —
с `{% %}`, а для проверки — отрендеренный дефолт 1a (30 дней, фильтров нет,
свитки на дефолтах, области нет).

Запустите **1a**: зелёное, ~1–2 с (предагрегаты, запрос лёгкий), строк
~150–400 (1 строка kpi + УС-3 + УС-4 + специализации + стримы + AD топ-40 +
2 строки тим-лидов). Красное — пришлите текст ошибки целиком.

## Шаг 2 — создать датасет pa_aud_v1

Datasets → создать виртуальный датасет на базе CROSS со схемой prod_proteus,
SQL = файл 1, имя **pa_aud_v1**. Затем вручную добавить 12 «Измерений» (без
них поля не попадут в `data` виджета):

| Поле | Тип | Назначение |
|---|---|---|
| section | abc | 'kpi' (итоги) \| 'cut' (строки разрезов) |
| cut_key | abc | lvl3 / lvl4 / spec / stream / adg / heads / report |
| cut_val | abc | значение разреза (у report = id отчёта строкой) |
| parent | abc | блок УС-3 для lvl4-строк, иначе пусто |
| nm | abc | подпись (название отчёта для report) |
| users | num | зрители |
| users_prev | num | зрители прошлого периода (у квартала пусто) |
| views | num | просмотры |
| views_prev | num | просмотры прошлого периода |
| new_users | num | первое касание в окне |
| regular_users | num | 8+ активных бакетов |
| once_users | num | ровно 1 бакет |

Мер не нужно — агрегаций нет, ИТОГО приходит kpi-строкой из SQL. В превью
датасета — те же ~150–400 строк, что дал 1a.

## Шаг 3 — создать чарт «Аудитория»

Charts → + Chart → датасет **pa_aud_v1** → визуализация eCharts (как у тела)
→ вкладка с кодом → вставить файл 2 целиком → Save.

В «Измерениях» чарта добавить те же 12 полей. **Лимит строк поставить
1000** — дефолтные 10 000 не страшны, но меньше 400 нельзя: хвост УС-4
и AD-топ обрежется молча.

Проверка на превью чарта: шапка «Аудитория: весь Proteus» + чип «за 30
дней», 5 KPI-карточек, синяя строка «Что видно в данных» (раскрывается),
сегменты разрезов (активен «УС-3»), таблица с полосами и ИТОГО сверху.

## Шаг 4 — поставить панель на борд 60260

В редакторе борда перетащите чарт в ряд ПОД телом «Отчёты и динамика» —
это и есть объединённый экран из задачи. Ширина — как у тела, высота —
на глаз (панель резиновая, длинная таблица прокручивается внутри строки).
Либо напишите имя созданного чарта — поставлю слот amend-ом через MCP сам.

## Шаг 5 — скоупы кросс-фильтров

В настройках кросс-фильтров борда (скрещенные воронки у каждого чарта):

- **новый чарт «Аудитория»**: область действия = **pa_cohorts**, СЕБЯ
  исключить, тело НЕ добавлять — клик по строке панели не должен
  перезапрашивать куб тела;
- **788805 (тело)**: ДОБАВИТЬ новый чарт к `pa_cohorts`. Это первое
  изменение скоупа тела с v5, и оно обязательное: панель должна слышать
  клики по каталогу (смена области). В отличие от полки, запрос панели
  лёгкий (~400 строк против 23 тыс. справочника);
- **полка** (если ещё стоит на борде): добавить новый чарт в её скоуп —
  период/свитки/люди должны резать и аудиторию, иначе её цифры разойдутся
  с телом. Полку позже снимете — не страшно, дефолты те же, фильтры приедут
  полоской настроек;
- **pa_cohorts**: ничего не эмитит, без изменений.

## Что должно появиться на экране (чек-лист)

1. Вход без выбора: «Аудитория: весь Proteus», чип «за 30 дней»; зрители
   и просмотры KPI совпадают с шапкой тела за 30 дней (свитки на дефолтах —
   источник один и тот же).
2. Клик по отчёту в каталоге тела → шапка панели показывает имя отчёта,
   цифры пересчитались (~секунда). Сегмента «Отчёты области» НЕ появилось —
   он только для люди-разрезов.
3. Клик по строке УС-3 в каталоге тела → пилюля «УС-3: <значение>»,
   появился сегмент «Отчёты области» и топ-25 отчётов этой аудитории.
4. Клик по строке разреза в таблице панели → пересчитались ТОЛЬКО когорты;
   панель и тело не мигнули.
5. Клик по отчёту в «Отчётах области» → когорты пересчитались на этот
   отчёт; панель и тело не перерисовались (куб тела тяжёлый — так решено).
6. AD-строки клика не имеют — тултип предупреждает: когорты по AD-группе
   пока не считаются (хвост следующей поставки когорт).
7. «Что видно в данных» раскрывается/закрывается; на 30 днях / неделях /
   месяцах у KPI есть дельта к прошлому периоду, на квартале — плашка
   «не сравнивается».
8. Период «12 месяцев» на полке (если стоит) → панель пересчиталась, чип
   «за 12 месяцев».
9. Область без зрителей за период → нота «Аудитория без данных», не дыра.
