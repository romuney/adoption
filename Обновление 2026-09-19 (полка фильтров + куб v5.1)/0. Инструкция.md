# Обновление 2026-09-19: полка фильтров + куб v5.1

## Что это и зачем

Четвёртый виджет дашборда — **полка фильтров** (левый сайдбар макета).
С момента v5 самовлияние тела отключено, поэтому сменить период и применить
люди/отчётные фильтры может ТОЛЬКО внешний чарт — эта полка. Она одна
эмитит маску кросс-фильтра, её читают оба куба:

- **куб v5.1** (тело 169602 и когорты 169589): в джиню добавлены 15 колонок
  полки — период, отчётные фильтры (отчёт/коллекции/владельцы/авторы/
  свитки) режут факт, люди (УС/стрим/специализация/AD-группа/тим-лиды) —
  атрибуты сотрудников. Без маски рендерится дефолт — это те же настройки,
  что включённые свитки макета;
- **новый датасет `pa_dicts`** — справочник значений для списков полки
  (~23 тыс. строк: отчёты, коллекции, владельцы, авторы, дерево УС, стримы,
  специализации, AD-группы).

**ВАЖНО — цифры изменятся даже без всяких фильтров.** Дефолтные свитки
макета («Только опубликованные», «Только актуальные», «Исключить владельцев
из просмотров») включены ПО УМОЛЧАНИЮ и зашиты в джиню как дефолт: не
опубликованные, не актуальные отчёты и просмотры владельцем собственного
отчёта из цифр уходят. Против вчерашней v5 итоговые числа станут МЕНЬШЕ —
это не поломка, это ТЗ макета. Снимаете свиток в полке — цифры растут
обратно.

Форма ответа обоих кубов не менялась (36 и 8 колонок, те же имена и типы):
чарты, «Измерения» и скоупы тела/когорт между собой — НЕ трогаем.

## Шаг 1 — проверить все SQL в SQL Lab (без датасетов)

SQL Lab, база CROSS/prod_proteus. Джиню SQL Lab не рендерит, поэтому файлы
1 и 2 — с `{% %}`, а для проверки — отрендеренные дефолты 1a и 2a (30 дней,
фильтров нет, свитки на дефолтах). Запустите по очереди:

1. **1a (тело)**: зелёное, время = замер входа. Ожидание ≈ как у v5, если
   вход **дольше 12 с** — не продолжайте, напишите мне. Красное — пришлите
   текст ошибки целиком.
2. **2a (когорты)**: зелёное, ~1–2 с. Красное — текст ошибки целиком.
3. **3 (pa_dicts)**: зелёное, ~23 000 строк (столбцы section/k/nm/parent).
   Заметьте время. Красное — текст ошибки целиком.

## Шаг 2 — создать датасет pa_dicts

Datasets → создать виртуальный датасет на базе CROSS со схемой
prod_proteus, SQL = файл 3, имя **pa_dicts**. Затем в датасете вручную
добавить четыре «Измерения» (без них поля не попадут в `data` виджета):

| Поле | Тип |
|---|---|
| section | abc |
| k | abc |
| nm | abc |
| parent | abc |

Мер не нужно — полка ничего не агрегирует. В превью датасета должно быть
~23 тыс. строк.

## Шаг 3 — заменить SQL в датасете тела (169602)

Datasets → `pa_body_v42` → Edit → заменить SQL целиком на файл 1 →
сохранить. Время сохранения должно совпасть с прогоном 1a в SQL Lab.
«Синхронизация столбцов» и «Измерения» НЕ требуются: форма ответа та же.

Откат, если что-то не так: прежний SQL — файл 1 из папки
«Обновление 2026-09-18 (v5 все разрезы сразу)».

## Шаг 4 — заменить SQL в датасете когорт (169589)

## Шаг 5 — создать чарт полки

Charts → + Chart → датасет **pa_dicts** → визуализация eCharts (как у тела
и когорт) → вкладка с кодом → вставить файл 4 целиком → Save.

В «Измерениях» чарта добавить те же 4 поля (section/k/nm/parent, abc).
**Лимит строк чарта поставить 30 000** — дефолтные 10 000 обрежут
справочник, и хвост списков (владельцы, авторы) молча пропадёт.

Проверка: на превью чарта — белая колонка «Фильтры»: кнопка «Сбросить»,
сегмент 30 дней / 20 недель / 12 месяцев / 8 кварталов, группы «Отчёты» /
«Сотрудники» / «Опции» со счётчиками, в «Опциях» — один включённый свиток
«Исключить владельцев из просмотров». Кликните «12 месяцев» — превью
перезапросится (это эмит).

## Шаг 7 — скоупы кросс-фильтров

В настройках кросс-фильтров борда (скрещенные воронки у каждого чарта):

- **чарт полки**: область действия = **788805 (тело) + pa_cohorts**,
  себя исключить. Иначе полка будет перечитывать собственный справочник
  23 тыс. строк на каждый чекбокс;
- **788805 (тело)**: НЕ менять — только `pa_cohorts`, как настроено в v5.
  Полку в его скоуп НЕ добавлять: клик по строке тела не должен трогать
  справочник;
- **pa_cohorts**: ничего не эмитит, без изменений;
- флажок кросс-фильтров на борде включён (уже так).

## Что должно появиться на экране (чек-лист)

1. Слева — белая полка без рамки: «Фильтры» + «Сбросить», под ними сегмент
   периода (активна «30 дней»).
2. Группы «Отчёты» / «Сотрудники» / «Опции» разворачиваются, в заголовке —
   счётчик активных условий группы.
3. Списки открываются в оверлее: поиск по списку, чекбоксы, «Снять всё»,
   счётчик выбранных; триггер показывает «Все X» / значение / «N условий».
4. «Управленческая структура» — дерево блок → департаменты; выбор блока
   без департаментов — самостоятельное условие.
5. Свитки: «Только опубликованные» и «Только актуальные» — ВКЛ (дефолт),
   «Исключить владельцев из просмотров» — ВКЛ, «Только сертифицированные»
   и «Только тим-лиды» — выкл.
6. Значки ⟳ на списковых фильтрах и «i» у «Авторов», «Тим-лидов»,
   «Исключить владельцев» показывают подсказки.
7. Клик «12 месяцев» → тело и когорты пересчитались; цифры отличаются
   от вчерашних (дефолтные свитки, см. вверху) — это ожидаемо.
8. Выбор отчёта → тело показывает только его, когорты пересчитались,
   триггер полки показывает название, счётчик группы = 1.
9. Включение «Только сертифицированные» → цифры ещё раз уменьшились
   (запрос ушёл в SQL, а не просто в браузере).
10. «Сбросить» → все три группы по нулям счётчиков, «Все X» на триггерах,
    цифры вернулись к дефолту. Полка при этом НЕ перезагружает саму себя.
11. Клик по строке тела: полка не мигает (справочник не перечитывается),
    пересчитываются только когорты.

## Отклонения от макета (сознательные, проговорены 18–19.09)

- **Поиска по логину/ФИО нет**: кросс-фильтр платформы умеет только точный
  IN (подстроки нет), 46 тыс. логинов списком не увезти, ФИО в витрине нет.
  Вернём, если появится оператор подстроки или отдельный людской датасет.
- **«Название отчёта» — мультиселект**, а не текстовый ввод: причина та же —
  подстрочного поиска у кросс-фильтра нет. Список с поиском внутри оверлея.
- **Чипов фильтров в шапке тела нет** (в макете они там): чарт не может
  читать чужую маску. Статус выбора виден в самой полке: «N условий» на
  триггере + счётчики групп.
- **Кнопки «Применить» нет**, как в макете: каждый клик сразу уходит
  запросом, платформа отменяет устаревшие — побеждает последний.
