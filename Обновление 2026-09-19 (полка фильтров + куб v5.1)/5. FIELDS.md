# FIELDS — поля для «Измерений» Proteus

Поля из SQL не попадают в `data` автоматически. Каждое поле нужно вручную
добавить в панель «Измерения» с точным именем.

Правило синхрона: **имя в SQL == имя в «Измерениях» == ключ в `CFG.fields`**.
Любое расхождение — поле не дойдёт до графика (RETRO 17).

Типы в Proteus: `f(x)` — вычисляемое, `#` — число, `abc` — строка.

## Поля графика — виджет 1: тело, `pa-reports-body.chart.js` (чарт 788805)

Датасет **pa_body_v42** (id 169602; SQL внутри — шаблон v5.1: все разрезы
одним ответом + люди/отчётные фильтры полки). 36 колонок — форма не менялась
с v3/v4: смена SQL не требует ни пересборки «Измерений», ни «Синхронизации
столбцов».

| Поле (точное имя) | Тип | Назначение |
|---|---|---|
| section | abc | секция: rep / grp / ov / total — ВСЕ в одном ответе |
| grain | abc | грануляция: d/w/m/q |
| dashboard_id | # | id отчёта (rep) |
| group_key | abc | collection / owner (grp) |
| group_val | abc | значение группы (grp) |
| cut_key | abc | lvl3 / spec (ov) |
| cut_val | abc | значение среза людей (ov) |
| cohort_month | abc | заглушка NULL — когорты в своём датасете |
| cohort_size | # | заглушка 0 |
| dash_nm | abc | название отчёта |
| owner_login | abc | владелец отчёта |
| colls | abc (Array(String), JSON-строкой) | коллекции отчёта |
| published | # | признак публикации |
| certified | abc | кем сертифицирован (в UI больше НЕ рисуется) |
| created_dt | # (DATETIME, epoch) | дата создания отчёта |
| users, users_prev | # | пользователи за период / предыдущий |
| views, views_prev | # | просмотры за период / предыдущий |
| new_users, new_users_prev | # | новые пользователи |
| regular_users, regular_users_prev | # | постоянные (8+ раз) |
| sleeping_users | # | не заходили >30 дней |
| views_per_user | # | просмотров на пользователя |
| last_view_days | # | дней с последнего просмотра |
| freq_1 … freq_5 | # | корзины частоты «1»/«2–3»/«4–7»/«8–15»/«16+» |
| ts_k | abc (Array(Int64), JSON-строкой) | возраст бакета от max_date |
| ts_users, ts_new, ts_react | abc (Array(UInt64)) | пользователи/новые/вернувшиеся по бакетам |
| ts_views | abc (Array(Int64)) | просмотры по бакетам |

«Вернувшиеся» (ts_react): не заходили последние **7 дней** (грануляция d)
или предыдущий бакет (w/m/q) — окно задаётся 4-м элементом GRAINS в
`.gen_cube5.py`.

Кросс-фильтр (эмит тела): `mode_param` (report/collection/owner/cut:lvl3/
cut:spec — разрез ПОСЛЕДНЕГО одиночного выбора) + `sel_f` (значение
одиночного выбора). `scope_param` в v5 НЕТ. Маску `mode_param/sel_f` читает
ТОЛЬКО датасет когорт: тело самовлияние не использует (отключено владельцем
в UI) и не нужно — все разрезы приходят одним ответом, смена вкладки
клиентская.

С v5.1 тело и когорты — ещё и ПРИЁМНИКИ маски полки (колонки `period_param`
и `*_f`, см. «Виджет 3»): люди-условия фильтруют атрибуты (attrs), отчётные —
факт (evd). Эмит-колонки полки в SELECT приёмников НЕ выводятся — платформа
несёт их в маске кросс-фильтра (фильтр по ARRAY-колонке в SELECT роняет CH).

### Виджет 2: закрепляемость — `pa-cohorts.chart.js` (чарт pa_cohorts)

Датасет **pa_coh_v4** (id 169589). 8 колонок:

| Поле (точное имя) | Тип | Назначение |
|---|---|---|
| section | abc | coh / rcoh / gcoh / ocoh |
| sel_key | abc | report / owner / collection / lvl3 / spec / … |
| sel_val | abc | значение выбора (id, логин, название) |
| sel_nm | abc | человекочитаемое имя выбора (имя отчёта) |

Приёмник кросс-фильтра тела, сам НЕ эмитит. Выбор рисуется пилюлькой
в заголовке (единый стиль с чипами тела). Лимит строк 10 000.

## Поля графика — виджет 3: полка фильтров, `pa-shelf.chart.js` (чарт новый)

Датасет **pa_dicts** — НОВЫЙ виртуальный над `prod_proteus.proteus_adoption`
(SQL — файл 3 поставки 2026-09-19). Все секции справочника одной таблицей,
~23 000 строк (own 7858 + auth 4814 + rep ~6152 + adg 3374 + coll 1363 +
lvl3/lvl4/stream/spec ~100).

| Поле (точное имя) | Тип | Назначение |
|---|---|---|
| section | abc | секция: rep / coll / own / auth / lvl3 / lvl4 / stream / spec / adg |
| k | abc | ключ значения (у rep = dashboard_id строкой) |
| nm | abc | подпись для списка |
| parent | abc | блок lvl3 для lvl4-строк (дерево УС), иначе `''` |

Лимит строк чарта **30 000**. Порядок секций и сортировка списков — в JS
полки (`CFG.order`, сортировка по nm); от порядка строк в ответе виджет
не зависит.

Эмит полки — 15 колонок, все с operator `IN` (свитки несут `'0'/'1'`;
`value=[]` НЕ эмитится — пустой список роняет запрос; полный сброс =
`applyCrossFilter([])`): `period_param`, `rep_f`, `coll_f`, `own_f`,
`auth_f`, `pub_f`, `act_f`, `cert_f`, `lvl3_f`, `lvl4_f`, `stream_f`,
`spec_f`, `adg_f`, `heads_f`, `exc_f`.

Дефолты `pub_f/act_f/exc_f = '1'` зашиты в джине куба (как включённые
свитки макета): полка эмитит свиток ТОЛЬКО когда он отличается от дефолта.
Период — константы JS (30 дней/20 недель/12 месяцев/8 кварталов), в data
его нет; дефолт `period_param='d'` — тоже в джине.

## Что считается в JS, а что в SQL

| Расчёт | Где | Почему |
|---|---|---|
| views_per_user, regular_users | SQL (внешние выражения) | форма ответа 36 колонок под form_data чарта |
| доли, дельты, медианы когорт, MAU, freq-срез | JS | правило 2 скилла |
| фильтрация вкладок друг по другу | JS (meta + grp/ov-строки) | без похода в базу |
| дедуп-агрегация mix-выбора | JS (DEDUP) | без похода в базу |
