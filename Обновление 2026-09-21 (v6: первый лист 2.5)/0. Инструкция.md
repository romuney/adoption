# Обновление 2026-09-21: v6 — первый лист макета 2.5

## Что это и зачем

Перестройка первого листа дашборда под [макет 2.5](../Макет/Архитектура%202.5.md):
правая часть экрана становится отдельным чартом, тело худеет до каталога,
большая полка фильтров заменяется узкой полоской настроек.

Что меняется на экране:

- **Тело «Отчёты» (чарт 788805)** — остаётся каталогом с тремя разрезами
  (отчёты / коллекции / владельцы), KPI и наблюдениями. Из него УХОДЯТ:
  правая панель динамики, частотная полоса, людские разрезы подшапки.
  Вместо них — заголовок «Отчёты», подпись «область: …» и **чипы активных
  условий** (приходят из нового поля `state_j`: свитки полоски, люди
  из «Кто смотрит», корзина частоты). Чипы информационные, без крестика —
  снимаются в своих чартах.
- **НОВЫЙ чарт «Кто смотрит»** (правая колонка) — внутри два таба:
  «Кто смотрит» (поимённый список с группировками, корзинами частоты,
  настройками) ⇄ «Динамика» (тот же график, что был в теле). Клик по
  группе / человеку / корзине = **людская шина**: сужает тело, сам чарт
  себя не перечитывает.
- **НОВЫЙ чарт-полоска** (верхняя строка) — период + три свитка
  (опубликованные / актуальные / без просмотров владельцев) + сброс.
  Заменяет полку фильтров на этом листе.
- **Когорты (169589)** — только смена SQL, виджет не меняется.

Куб v6 считает на предагрегатах `prod_proteus.pa_*` — вход должен стать
**быстрее** v5.1. Форма ответа: тело 36 → **37 колонок** (+`state_j`),
когорты не меняются (8), pa_who — 20.

**Откат.** Пока эта поставка не применена, действует поставка 2026-09-19
(полка + куб v5.1). Если что-то пойдёт не так — SQL обоих кубов возвращается
файлами 1 и 2 из той папки, новые чарты удаляются, полка ставится на место.

## Шаг 1 — проверить все SQL в SQL Lab (без датасетов)

SQL Lab, база CROSS/prod_proteus. Джиню SQL Lab не рендерит, поэтому
проверяются отрендеренные дефолты (30 дней, фильтров нет, свитки на
дефолтах). По очереди:

1. **1a (тело v6)**: зелёное. Заметьте время — это новый вход борда.
   Ожидание — заметно быстрее v5.1 (предагрегаты). Вход **дольше 12 с** —
   не продолжайте, напишите мне. Красное — пришлите текст ошибки целиком.

   > **Как мерить.** Замер — только ПЕРВЫЙ прогон уникального текста. Второй
   > прогон того же файла вернёт сохранённый результат, а не посчитает заново
   > (проверено 22.09: 16,42 с → 1,57 с на одном и том же тексте). Нужен
   > повторный замер — добавьте первой строкой `-- 2` (комментарий меняет ключ
   > кэша, план запроса не меняет). И помните про холодные данные: самый первый
   > запрос за долгое время читает с диска и потому медленнее обычного.
2. **2a (когорты)**: зелёное, ~1–2 с. Красное — текст целиком.
3. **4a (pa_who)**: зелёное, до ~2 200 строк (секции list/ctx/freq/ts/total,
   столбцы как в файле 4). Дольше 8 с — напишите мне. Красное — текст целиком.

## Шаг 9 — приёмка связки

После F5, по очереди:

1. **Клик по отчёту в каталоге** → когорты пересчитались (пилюлька
   отчёта), «Кто смотрит» пересчитался под область, тело НЕ перезапросилось.
2. **Клик по человеку в «Кто смотрит»** → тело сузилось, в шапке чип
   «Человек: <логин>» без крестика; сам список не перезапросился.
3. **Корзина частоты** → у тела чип «Частота: …», список сузился локально.
4. **Полоска: период «12 месяцев»** → тело, «Кто смотрит» и когорты
   пересчитались; подпись периода в теле изменилась.
5. **Свиток «включая неопубликованные»** → чип у тела, цифры выросли.
6. **Сброс полоски** → чипы условий у тела исчезли.

Любое красное или подозрительное — стоп и мне текст/скрин целиком.

## Известные ограничения (не поломки)

- В чипе «Люди: N» человек подписан **логином** — ФИО в кубе нет, добавим
  с колонками `pa_emp_attrs` следующим шагом.
- Подпись «область: …» у тела не знает название людской шины — остаётся
  названием выбора каталога; сама шина видна чипами.
- Группировка «AD-группа» в «Кто смотрит» показывает заголовки групп,
  но не людей внутри (в ответе нет членств) — клик по группе шину пишет.
- Грануляция «Кто смотрит» выводится из числа бакетов динамики; в списке
  ФИО и стаж — заглушки до attrs (см. FIELDS.md, виджет 6).
