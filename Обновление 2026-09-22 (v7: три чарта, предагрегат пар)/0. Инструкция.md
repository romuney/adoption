# Обновление 2026-09-22: v7 — лист «Отчёты» из трёх чартов, предагрегат пар

## Что это и зачем

Лист «Отчёты» собирается из **трёх чартов на трёх датасетах**, вместо
четырёх–пяти в v6:

| Было (v6, поставка 2026-09-21) | Стало (v7) |
|---|---|
| полоска на pa_dicts (справочник 23 тыс. строк исполнялся на каждом входе) | **тонкая шапка листа** на pa_strip (одна строка, таблиц не читает): период и переключатели «Считать» |
| тело: каталог + KPI (при Shift-выборе KPI **приблизительные**) | каталог-селектор области слева (16 колонок вместо 37) |
| «Кто смотрит» ⇄ «Динамика» на pa_who | **«Аудитория области»** справа: 5 KPI + «Что видно в данных» сверху, под ними вкладки «Динамика» · «Кто смотрит» · «Закрепляемость» — один датасет pa_people |
| когорты отдельным чартом на pa_coh_v4 | вкладка «Закрепляемость» той же панели |

Логика связки на экране: **слева выбираете ЧТО** (отчёты / коллекции /
владельцы — клик, Shift накапливает) → справа видите **КТО и СКОЛЬКО** по
этой области. **Справа выбираете людей** (группу, человека, корзину частоты)
→ каталог слева сужается до их отчётов. **Над каждым чартом — строка «Выбранные
фильтры»** постоянной высоты: только выбранное в ЭТОМ чарте — пилюлями с ×
(снимается здесь же); выбор соседнего чарта здесь не дублируется. **Шапка сверху** — период и переключатели.

Скорость (стенд с синтетикой вдвое больше боевого факта):

| Запрос | v6 | v7 |
|---|---|---|
| каталог (вход, 30 дней) | 5,6 с | 0,65 с (на pa_pair) |
| каталог, 20 недель | 13 с | 0,7 с |
| правая панель (who + когорты + KPI) | 21 + 0,4 с | 0,64 с одним запросом (на pa_pair + pa_dash_bkt) |
| правая панель, 20 недель | — | 0,75 с |

На бою абсолютные цифры другие — их даёт шаг 2 (SQL Lab). На стенде
сократилось число чтений факта: pa_who читал его **11 раз** за запрос,
каталогу и pa_people дневной факт не нужен вовсе: оба читают предагрегат пар
`pa_pair`, линию «Просмотры» динамики pa_people берёт из `pa_dash_bkt`.

**Правая панель 2026-09-23 (жалоба «клик — 6–7 секунд справа»)**: pa_people
переведён с дневного факта на `pa_pair` (как каталог) + новую маленькую таблицу
`pa_dash_bkt` (отчёт × период: просмотры). На стенде ответ панели на клик по отчёту
быстрее в 2–3 раза (весь Proteus 1,43 → 0,64 с; 20 недель 2,08 → 0,75 с) — на
уровне каталога. Для этого нужен новый GP-параграф (шаг 1) — без него берите
запасной файл **3b**.

Что исправлено попутно (было в бою или в поставке v6):

1. Shift-выбор нескольких отчётов: v6 отправлял правым чартам только
   ОДИНОЧНЫЙ выбор — при мультивыборе «Кто смотрит» и когорты откатывались
   ко всему Proteus. Теперь уходит вся область.
2. KPI при мультивыборе считались формулой из макета (`DEDUP`), а не
   данными. Теперь KPI — точные уникальные люди области.
3. Фильтр по AD-группе ронял запрос (`hasAny` получал кортеж, а не массив);
   выбор коллекции ронял pa_who тем же способом.
4. «Не заходили больше 30 дней» при периоде 30 дней было всегда 0 —
   заменено на «ушедшие»: были в прошлом периоде, в текущем нет.
5. Корзина частоты в каталоге фильтровала по парам «отчёт×день», а
   «Кто смотрит» показывал корзины по дням: клик по корзине давал другое
   число людей. Теперь обе стороны — по активным периодам, числа сходятся.
6. «Кто смотрит» в v6 рисовался без стилей (классы разметки без префикса):
   браузерные кнопки, голая таблица.
7. Когорты: возраст, в котором никто не вернулся, сдвигал все ячейки
   правее на столбец.
8. Смена вкладки каталога перезапрашивала правые чарты впустую.
9. Вкладки каталога не фильтровали друг друга по коллекциям: массив
   коллекций приходит от Proteus в Python-виде `['a', 'b']`, виджет ждал JSON
   и считал, что у отчётов коллекций нет. Теперь: выбрали коллекцию — во
   «Отчётах» только её отчёты, во «Владельцах» — их владельцы; выбрали
   владельца — только его отчёты и коллекции.
10. «Кто смотрит» → Настройки («Только руководители», «Исключить логины»)
   действовали только на список; теперь сужают и каталог
   (новый носитель `exl_f`). Группа «Остальные» в разрезе «Тим-лиды»
   фильтровала наоборот — по руководителям.

**Откат.** До шага 4 ничего на борде не меняется. Если что-то пойдёт не так
после — действует поставка 2026-09-19 (куб v5.1 + полка) или 2026-09-21
(v6), в зависимости от того, что стоит сейчас: SQL датасета 169602 и JS
чарта 788805 возвращаются из её файлов, новые чарты снимаются с листа.

## Шаг 7 — приёмка (F5 борда)

1. Вход: над каталогом — строка «Выбранные фильтры» с подсказкой (условий нет); над
   правой панелью — пустая строка той же высоты (подпись одна на лист, пилюли панели
   появляются в ней без сдвига карточек); справа пять KPI
   и открыта вкладка «Динамика» — оба графика растянуты на высоту карточки;
   ИТОГО каталога во вкладке «Коллекции» = KPI «Пользователей» справа.
2. **Клик по отчёту** → над каталогом пилюля «Отчёт: …» с ×, над правой панелью
   пилюли НЕТ (там только выбранное в самой панели); правая панель обновилась
   примерно за то же время, что каталог при смене периода; KPI «Пользователей» справа = числу в строке каталога
   **до единицы**; каталог не перезапросился; **карточки не сдвинулись ни на
   пиксель** (строка фильтров постоянной высоты). × на пилюле снимает выбор.
3. **Shift по второму отчёту** → над каталогом две пилюли, пользователей **меньше
   суммы двух строк** каталога (один человек — один раз).
4. **Вкладка «Коллекции» каталога** → правая панель НЕ перезапрашивается.
5. Оставьте в каталоге ОДИН выбранный отчёт. **Справа «Кто смотрит» →
   Вид «Оргструктура» → клик по блоку УС-3** → каталог перезапросился, над правой
   панелью пилюля «УС-3: …» с ×, над каталогом — ничего нового; строка выбранного
   отчёта = числу людей блока в дереве
   справа (KPI справа не меняются: они про всю область, выбор людей подсвечен).
6. **Клик по человеку, Shift по второму** → справа «выбрано: 2», оба
   подсвечены, список не схлопнулся; над правой панелью пилюли с ФИО.
7. **Корзина частоты** → ИТОГО каталога = числу людей корзины; выбранная корзина
   видна целиком (не обрезана сверху). **Переключите период на 12 месяцев** —
   корзины станут «1 · 2–3 · 4–6 · 7–12 месяцев», выбор остаётся той же
   по счёту корзиной (2–5 дней → 2–3 месяца), каталог пересчитался. При выбранной
   корзине KPI сверху и сводная таблица «Кто смотрит» — по людям этой корзины
   («Пользователей» = числу на корзине, «из N в области»; дельты — «не сравнивается»).
6e. **Каталог: колонка «Ритм»** вместо «Тишины» — Ежедневно / Еженедельно / Ежемесячно /
   Эпизодически: как пользуется отчётом хотя бы половина его пользователей (ежедневно — 12+
   дней из 30, еженедельно — 6+ недель из 8, ежемесячно — 2 из последних 3 месяцев). В
   подсказке строки — людей каждого ритма. Клик по «Ритм» — сортировка (чаще — выше).
   Пустая колонка — не добавлено поле `rhythm` в «Измерения».
6d. **«Кто смотрит» — все зрители.** Сумма чисел четырёх корзин = KPI «Пользователей»;
   счётчик над таблицей «N человек» = KPI. Клик по любой корзине (в т. ч. «1 день» большой
   области) показывает всех её людей, «Показано 1–50 из N» = числу на корзине.
   KPI «Постоянных» = сумме корзин 3 и 4: 6+ дней или недель, 4+ месяца, 3+ квартала
   (столбец «Пост.» каталога — та же мера). В уровне УС нет строк «-»/«…»: заглушки
   оргструктуры обрывают путь, такие люди — в одной строке «—».
6c. **Скорость клика**: файл **3c** (клик по одному отчёту; id отчёта — вместо

## Известные ограничения

- Вид «AD-группа» в «Кто смотрит» по умолчанию ВЫКЛЮЧЕН (в меню «Вид» его нет).
  У сотрудника на бою сотни AD-групп: их разворот добавлял ~2 с к КАЖДОМУ клику
  (замер SQL Lab 2026-09-23: один отчёт 2,33 с; стенд с реальным числом групп:
  1,2 с → 0,16 с без них). Нужен — в файле 3 поставьте `{% set WITH_ADG = true %}`
  (строка 28), панель станет медленнее. Людей внутри AD-группы в ответе нет и тогда.
- Итоги групп в «Кто смотрит» и KPI: корзина частоты и настройки списка («Только
  руководители», исключения) пересчитывают их по отобранным людям (сравнения с прошлым
  периодом тогда нет). Поиск и выбор групп итоги не меняют — для них колонка «В выборке».
- Людская шина сужает только каталог. Динамика и когорты справа
  остаются по всей области: панель держит контекст, выбор людей подсвечен
  (панель не может фильтровать сама себя — самовлияние в Proteus выключено).
- Строка фильтров чарта показывает только его собственный выбор: кросс-фильтр
  соседа Proteus не даёт снять из другого чарта, поэтому он там и не дублируется.
- «Дней» в списке людей — активных периодов грануляции: на 20 неделях колонка
  называется «Недель», на 12 месяцах — «Месяцев» и т. д.
- Корзины частоты — по числу активных периодов, своя шкала у гранулярности:
  четыре корзины: 30 дней и 20 недель — 1 · 2–5 · 6–15 · 16+; 12 месяцев — 1 · 2–3 ·
  4–6 · 7–12; 8 кварталов — 1 · 2 · 3 · 4+ (в витрине 13 месяцев истории). Постоянные —
  корзины 3 и 4.
- Сравнение с предыдущим периодом есть только для 30 дней и 20 недель.
