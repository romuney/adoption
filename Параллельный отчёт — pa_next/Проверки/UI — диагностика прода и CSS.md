14.11.2026. Источник: [запись владельца](<../диагностика на проде>), начало 18:05:41 UTC. Исходный файл сохранён без изменений.

## Подтверждённая причина высоты

CSS содержал правило `body:not(:has(#main-menu)) … { --pa-next-nav-height: 0px }`. В живом борде `#main-menu` не найден, но шапка начинается на 48 px. Отсутствие конкретного ID оказалось неверным признаком отсутствия верхней панели. Снимок не устанавливает её действительный селектор, поэтому новый CSS не угадывает другое имя.

| Размер | В записи с прода | После исправления в локальной модели |
|---|---:|---:|
| Высота окна | 963 px | 963 px |
| Верх шапки / высота шапки | 48 / 65 px | 48 / 65 px |
| Верх iframe | 129 px | 129 px |
| Резерв верхней панели | 0 px | 48 px |
| Высота iframe | 856 px | 808 px |
| Нижняя граница iframe | 985 px | 937 px |

Старая формула: `963 − 0 − 65 − 42 = 856`. Исправленная: `963 − 48 − 65 − 42 = 808`. Два пикселя загрузчиков после основного ряда и нижнее поле 24 px завершают сетку ровно на 963 px. В старой версии iframe выходил ниже окна на 22 px.

Удалено только автоматическое обнуление резерва по отсутствию `#main-menu`. Верхняя шапка и Edit не скрываются. Для отдельного встраивания без верхней панели можно явно задать нулевой резерв на целевой `.grid-container`; этот режим не относится к переданному борду. Дефолт 48 px соответствует измеренной геометрии, а не универсально измеряет меню любой высоты.

## Применить

Заменить **файл 9 целиком** в CSS нового дашборда и обновить страницу. Не добавлять поверх старого: прежнее правило с высокой специфичностью продолжит обнулять резерв.
