# Почему CSS не скрывал шапку в Proteus

Источник — полная [выгрузка с прода](<../pa-next-header-diagnostic (1).json>), добавленная владельцем в коммите `c4d16ea`. Прочитаны все 338 stylesheet; лимиты правил не достигнуты. Нужный блок v2 находится в `style.CssTemplate-css` под индексом 336. CSS вставлен и загружен: проблема не в отсутствии блока.

## Причина

Proteus оборачивает CSS борда в `CSSScopeRule` (`@scope`). В верхних правилах `body` уже заменён на `:scope`, но в правилах переключателя, вложенных в `@supports`, остаётся `body`. Браузер не применяет эти правила в области дашборда. В результате шапка сохраняет `position:static`, ссылки — `position:static` и кегль 14 px, Markdown-ряд — высоту 400 px.

Условия `@supports` активны. Адресаты ссылок существуют, обработчики не отменяют переход, fragment URL меняется. Результаты `Element.matches` сами по себе не доказывают применение CSS: они не выполняют проверку в контексте `@scope` и не учитывают каскад. Именно поэтому проверка v2 в обычном глобальном stylesheet не обнаружила проблему платформы.

## Изменение

В `tools/parallel/header_reveal.py` и сгенерированном CSS9 переключатель v3 использует явный `:scope`. В обычном stylesheet он соответствует корню документа, внутри `@scope` — корню области. Проверки `#app` учитывают три положения: ниже корня области, на самом корне и выше него. Последний случай нужен для новой Markdown-ссылки на корень SPA, когда CSS ограничен вложенным контейнером дашборда.

Старые ссылки на `#chart-id-859562` остаются рабочими. Строка управления обнуляется, пока график монтируется; если контрола или настоящего адресата нет, шапка остаётся штатной. Переключение по hover не добавлено. Клик по восьмипиксельной полосе под навигацией открывает и закрывает шапку, native focus/menu и режим редактирования сохраняют доступ к действиям. Условие редактирования учитывает также предка корня области.

## Проверка

`python3 tools/parallel/test_ui_header_scope.py` использует полный JS/iframe отчёта и точное дерево контрольного Markdown-ряда из продовой выгрузки. Стенд оборачивает CSS в реальные браузерные `@scope (#app)` и `@scope (.dashboard-container)`; точный selector корня продовой области старая диагностика не сохраняла, поэтому эти корни — проверяемые варианты стенда.

Старый CSS из `315d5f5` в обеих областях воспроизводит проблему: шапка не становится fixed, ряд сохраняет 400 px. Новый CSS проверяется в 12 сочетаниях: обычный stylesheet и две области × старые/новые ссылки × 1366×768 / 1920×1080. Проверяются реальные клики, закрытие, неизменность положения и размера iframe, навигации и прокрутки, снятие резерва шапки 65 px, отсутствие активации от hover, сохранение состояния после blur, меню и Edit через Tab. Принятые данные и число filter emissions должны оставаться неизменными.

Отдельно запускается прежний регресс `test_ui_header_focus.py`: пять вариантов обёртки/абзацев/позднего адресата, сломанные и blank-контролы, mixed row, keyboard/menu/Edit. Сборщик UI проверяется с `build_ui.py --check`, коллектор — с `test_header_diagnostics.py`.

Пройдены все 12 сочетаний, оба отрицательных контроля и пять прежних сценариев. Проверка сборщика UI, ESLint и статическая проверка изоляции поставки также прошли. Коллектор прошёл свой браузерный тест с 177 stylesheet. Метрики основного регресса — [header-scope-v3-results.json](header-scope-v3-results.json). ## Установка

На уже настроенном борде заменить **только файл 9 целиком в общем CSS дашборда**. Существующий Markdown оставить. JS4, SQL, YAML и ноду обновлять или запускать не нужно. Для запуска из закрытого состояния убрать из адреса fragment начиная с `#`: ссылки открытия сохраняют открытое состояние в URL.

Новая диагностика для этого исправления не требуется. Коллектор дополнительно научен сохранять `start/end` будущих `CSSScopeRule`, версию блока CSS и пояснение ограничения `Element.matches`.
