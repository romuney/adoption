# Договор сходимости

Оптимизация допустима только при сохранении чисел. Новый отчёт сравнивается с текущим отчётом на одинаковой дате данных, одинаковом наборе исходных событий и одинаковых фильтрах. Ускорение не оправдывает даже небольшое расхождение целочисленных показателей.

## Источник и эталон

- Источник факта — предоставленная владельцем `Proteus Adoption (4).yaml`, активный параграф «Финальная таблица из event_physical_report». В отчётах проверки сохраняется SHA-256 файла.
- До `2026-10-06` включаются только `dashboard.rendered`, начиная с `current_date - interval '15 months'`. Начиная с `2026-10-06` — только `proteus.dashboard.timeToFirstChartQuery`, с верхней границей `<= current_date` (полночь, не конец текущего дня). Асимметрия границ сохранена намеренно.
- Неиспользуемое поле исходного источника `max_date` заполняется `NULL::timestamp`: удалены два скалярных MAX по полному источнику, оно не читается ни одним последующим GP-параграфом. Все потребляемые поля и 12 базовых витрин сравниваются точно; равенство этого неиспользуемого поля не заявляется.
- JOIN с `usr_cross_data.bl_talent_management` сохранён: даже неиспользуемый далее атрибут может влиять на кратность исходных событий. Исправление возможных дублей — отдельная методологическая задача, не оптимизация.
- Прежние SQL до GP-ускорения закреплены коммитом `167c2edcfae1bee7a4fcd830052a9d2dfea49edb`. Это эталон из репозитория; совпадение именно с вручную установленными SQL следует проверить при парной установке.
- Файлы действующей поставки, исходные таблицы и пользовательский YAML не меняются. Новые записи/создания/удаления — только в пространстве `pa_next_`.

## Что обязано совпасть

| Область | Инвариант |
|---|---|
| Люди | Один канонический логин человека после существующей склейки. Уникальных зрителей нескольких отчётов и периодов нельзя суммировать. |
| Владельцы | Нормализация/склейка логинов владельцев, исключение владельцев и «Мои отчёты» дают прежние множества. |
| Просмотры | Сумма исходных `action_count` после прежних исключений и тех же окон; не количество строк таблицы. |
| Периоды | 30 дней, 20 недель, 12 месяцев, 8 кварталов, произвольные периоды и длинные окна имеют прежние границы и предыдущий период. |
| MAU | Последний закрытый месяц и прежняя логика сравнений, а не доля всех пользователей. |
| Целевая аудитория | Права и условия ЦА, объединение AD-групп и поимённых прав, вне ЦА, не заходили, руководители/штат/уволенные — прежние числители и знаменатели. |
| Закрепляемость | Прежние когорты, первый визит, возраст, регулярные/вернувшиеся/новые, маски и корзины частоты. |
| Каталог и панель | ИТОГО не заменяется суммой строк с пересечениями. `aa`, `ar` и `pv` согласованы с основными ответами. |
| Фильтры | Шапка влияет на каталог и панель; выбор каталога — только на панель; выбор людей панели — только на каталог. Самовлияние выключено. |
| Протокол | После смены выбора нельзя принять ответ под старый набор фильтров; части интерфейса показывают совместимые версии данных. |
| Доступ/кэш | Логин и параметры, влияющие на ответ, не исчезают из ключа кэша. Общий кэш не становится источником персональных чисел. |

## Автоматические проверки

`tools/parallel/verify_events.py` исполняет фактический старый и новый исходный SQL на локальном PostgreSQL в отдельной тестовой БД. Состав колонок одинаков; из сравнения значений исключено только `max_date` после проверки NULL в новой версии и отсутствия downstream-потребителей. Фикстура проверяет границу истории, переключение событий, полночь текущего дня, лишние типы событий, дубликаты событий и кратность JOIN. Это не запрос к корпоративным данным.

`tools/parallel/verify_numbers.py` выполняет старый и новый SQL в ClickHouse 24.8 (chdb 2.1.1) на одной синтетической базе. Требуются явно заданные `PA_DB`, полный коммит эталона и фактический YAML. Сравнение — мультимножество всех пяти колонок ответа с сохранением дублей; внутри упакованных `groupArray` сортируются только строки, значения не округляются и не обрезаются. Исключения — только новые служебные строки: `pa_next_version` отдельно обязана быть единственной и `ready`; три `pa_next_request` каталога/панели обязаны точно отражать nonce входных фильтров, иметь правильные имена владельцев и нулевое числовое поле. Они не участвуют в метриках.

Любая ошибка SQL, пустой ответ, NULL/NaN, отсутствие готовой версии или расхождение — FAIL. Совпадение текстов двух ошибок не считается совпадением чисел. Самопроверка компаратора: `python3 tools/parallel/verify_numbers.py --selftest`.

Матрица: все периоды/переключатели, один и несколько отчётов, владельцы/коллекции/оргструктура, условия ЦА, группы аудитории, людские фильтры, сегменты, произвольные периоды и невалидный/враждебный ввод. Режим `--modes` добавляет старый анализатор и Nullable-настройки; скорость оценивается только в основном профиле с новым анализатором и `prefer_column_name_to_alias=1`.

## Проверки рядом с текущим отчётом

1. Запустить новый ноут без одновременного запуска второй копии. Убедиться, что все параграфы завершились, новая дата данных совпадает со старой.
2. Открыть оба отчёта одним пользователем, сбросить фильтры. Сверить KPI, итог каталога, динамику, ЦА и людей для четырёх готовых периодов.
3. Повторить для одного отчёта, двух отчётов с общими зрителями, коллекции, владельца; затем для ЦА по правам и по условиям.
4. Проверить собственный период вокруг границ месяца/квартала и перехода событий `2026-10-06`, длинное окно и пустую выборку.
5. Повторить с «Без владельцев», опубликованными/актуальными, новым и старым логинами одного человека, «Мои отчёты».
6. Проверить людей из панели → каталог, группу аудитории из каталога → панель, быстро сменить несколько фильтров. Старый ответ не должен снимать ожидание нового.
7. Проверить двумя пользователями с разными логинами/правами и после обновления кэша. Производственные права и кэш нельзя доказать локальным стендом.
8. Снять время Network одинаковых состояний: первое открытие, повторное открытие, выбор отчёта, смена периода, фильтр по людям. Сравнивать при одинаковой свежести и состоянии кэша.

При расхождении не переносить чарты в действующий отчёт. Сохранить обезличенные условия, дату данных и названия расходящихся показателей; исправлять причину, а не вводить округление или допуск.
